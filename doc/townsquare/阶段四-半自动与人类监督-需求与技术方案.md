# 阶段四：半自动与人类监督（需求与技术方案）

## 1. 需求描述

### 1.1 目标

- 引入半自动模式（主持人可开启）
- AI 作出操作后，允许人类说书人修改状态或私聊玩家
- 人类监督者的操作需要以“附加消息”的形式进入 AI 上下文

### 1.2 人类可介入范围

- 修改玩家状态（死亡、无票、角色、座位等）
- 修改会话状态（提名、投票、夜晚/白天）
- 私聊或广播玩家

## 2. 技术方案（细化到模块）

### 2.1 模式控制

- 新增 `src/web/agent/mode.js`
  - 支持 `auto` / `semi`
  - `semi` 模式下，AI 先执行动作，再开启“人工覆写窗口”

### 2.2 人工覆写记录

- 新增 `src/web/agent/supervisorLog.js`
  - 记录人工修改操作：
    - 修改类型（chat/players/session）
    - 前后差异（diff）
    - 时间戳
    - 备注（可选）

- 在 Vuex 中新增 `supervisor` 模块用于存储日志

### 2.3 覆写入口与 UI

- `src/web/townsquare/components/AgentPanel.vue`
  - 增加“半自动模式”切换
  - 提供“监督者注释输入框”
  - 显示最近人工覆写记录

### 2.4 上下文附加机制

- `src/web/agent/contextBuilder.js`
  - 在每次推理前，把 `supervisorLog` 中最新记录附加进 Prompt
  - 使用“工具调用回放”格式，确保 AI 感知人类介入

### 2.5 AI 与人工冲突处理

- 执行顺序：AI 动作 → 人类覆写 → 记录附加
- AI 下一次推理必须读取最新覆写记录

## 3. 验收标准

- 主持人可开启半自动模式
- AI 动作后，主持人可修改状态或私聊
- 修改记录被写入 AI 上下文并可在 UI 中查看
