# BotC-AI 目标架构

## 架构目标

目标架构同时满足四个条件：严格执行可验证规则、把全部 Agent 编排留在房主浏览器、复用 townsquare 在线能力、支持多个 LLM 供应商与任意人机席位组合。

核心分层为“确定性规则内核、权限视图、统一动作协议、浏览器 Agent Runtime”。AI 不能绕开这些层直接修改魔典。

“Agent 运行在房主浏览器”指 Agent 循环、上下文、Skills、工具权限、记忆和调度均在该浏览器执行。云端或本地 LLM 端点只完成推理，不成为对局状态的权威方。

## 规则范围清单

规则范围是规则实现和对局版本选择的静态输入，不是可写对局状态。M1 使用 `knowledge/rulesets/m1-ruleset-scope.json` 冻结三个基础剧本、110 个角色以及 108 个规范概念；清单通过独立 Schema 和完整性哈希校验，并把三个中文官方概念目录固定到页面修订与原始 Wikitext 哈希。

概念模型由以下部分组成：

- `concepts` 保存稳定 ASCII ID、中文规范名称、实现责任、概念类别、中文别名、来源定位和关联概念。
- `conceptIndexes` 分别保存 80 个术语、31 个能力类别和 7 个重要规则主题的官方目录顺序；重叠内容复用同一概念 ID。
- `roleAbilityCategories` 为当前 110 个角色逐一保存中文官方能力类别页可核验的关联，空数组表示固定来源没有列出关联，不表示可以推测为任意类别。

实现责任为 `rules-kernel` 的概念进入后续确定性状态、命令与规则设计；`storyteller-adjudication` 由内核生成受约束的裁量任务；`reference` 只服务中文解释、检索和界面映射，不能直接产生状态变化。范围清单不包含规则正文；M1-R2 领域协议直接从清单派生不可变身份，不复制或另造规则集 ID。

## 领域状态与事件

当前已实现领域协议 `0.4.0`。协议模块不依赖 Vue、Vuex、WebSocket、DOM、Node 专用 API 或 LLM SDK，使用严格 Draft-07 JSON Schema 校验状态、命令、事件、命令回执和事件流。`game.create` 固定对局 ID、M1-R1 规则集身份、角色规则包身份与随机种子；M1-R4/M1-R5 提供基础阶段、生死、胜负、提名投票和流放，M1-R6 加入能力实例、来源条件、触发队列、持续/延迟效果和裁量任务，没有提供任意可写扩展容器。具体角色语义、通信与 Agent 字段仍由后续需求按版本演进。

权威状态至少包含：

- 对局身份：规则版本、剧本、随机种子、房间与阶段。
- 座位：控制者类型、玩家身份、真实角色、认知角色、阵营、存活、死亡票和席位连接状态。
- 效果：醉酒、中毒、保护、提名/投票修正、提醒标记、持续时间和来源。
- 流程：首夜/其他夜行动队列、白天计时、提名、投票、处决、胜负检查和待裁量任务。
- 通信：公开、阵营、点对点、玩家到说书人的消息元数据及投递状态。
- Agent：Prompt/Skill/模型版本、运行状态、预算和私有记忆引用；密钥不属于领域状态。

所有变更由命令触发，并产生可重放事件。典型链路为：

1. 人类 UI 或 Agent Skill 提交命令。
2. 权限层确认提交者能否执行该动作。
3. 规则内核依据当前状态和规则版本校验前置条件。
4. 需要裁量时，内核生成范围受限的裁量任务；AI 说书人只能从合法候选中选择或提供指定结构的结果。
5. 内核提交领域事件，归约器更新状态。
6. 视图层为不同接收者生成最小信息事件或快照。
7. UI、在线同步、Agent 观察与审计日志消费各自允许看到的结果。

命令总线要求每条命令携带唯一命令 ID 和 `expectedRevision`。信封与类型负载校验通过后，命令的规范化 JSON 使用浏览器兼容 SHA-256 形成指纹；相同 ID、相同内容返回首次持久化回执，相同 ID、不同内容拒绝。幂等查询早于修订校验，避免成功命令在状态前进后因重试被错误执行；过期的新命令和领域拒绝都不产生事件，但保留稳定回执。

处理器只能返回已注册的候选事件，不能直接获得内部状态写权限。事件 ID、连续序号、因果命令、执行者、记录时间、规则集与角色包身份由总线补齐；确定性反应器在每个候选事件归约后按固定顺序扩展连锁事件，单命令硬限制为 256 个。整批事件先在临时状态归约并通过 Schema、角色包白名单和扩展不变量，再原子提交；引擎内部与所有公开副本均深冻结。

事件流导出包含格式版本、协议版本、对局 ID、固定规则集/角色包身份、完整事件和命令回执。恢复时必须再次装载完全相同且校验通过的规则包，再从空状态逐条归约；处理器和反应器不会重跑。事件连续性、引用、队列顺序、用量、终态、包身份或成功命令边界不变量任一失败都停止可写恢复；`0.1.0` 至 `0.3.0` 旧版本不静默迁移。IndexedDB、检查点、跨版本迁移和防篡改签名属于后续需求。

基础规则模块与命令总线共同组成当前可运行的最小规则内核：

- `game.start` 校验唯一且从 `1` 连续的席位顺序、至少三名非旅行者和至少一名恶魔，把席位初始化为存活并进入首夜。角色类型只到镇民、外来者、爪牙、恶魔和旅行者，不代表具体角色规则已经实现。
- `nomination.open`、`vote.open`、`vote.record`、`vote.close` 建立每天一次的提名资格、以被提名者结束的环形投票顺序、存活人数过半门槛、死亡票消费、严格最高票与平票候选；逐席决定和结算都形成可重放事件。
- `exile.open`、`exile.support.set`、`exile.close` 使用独立的同时支持流程，按全部在场席位过半结算旅行者流放；它不消耗死亡票、不占常规提名或处决次数，成功后旅行者死亡但白天继续。
- `phase.advance` 固定执行 `first-night -> day -> night -> day` 并维护日号、夜号；活动窗口期间不能推进，有候选时不能按无人处决结束白天。
- `player.kill`、`player.revive` 和 `execution.resolve` 产生专用事件。活动窗口期间基础生死冻结；常规处决只作用于当前候选，区分“被处决”和“因处决而死亡”，未触发胜负时立即入夜。
- 每次真正死亡后立即检查常规胜负：没有存活恶魔时善良获胜，非旅行者存活数不超过二且仍有恶魔时邪恶获胜，同时满足时善良优先。
- Host/System 控制窗口并可代理明确席位；Seat 只能替自己的席位提名、投票或设置流放支持，Observer 与裸 Agent 无写权限。每个原子命令批次及重放成功命令边界都验证全部规则不变量。
- 对局精确绑定一个不可变角色规则包。能力实例引用包内定义和固定中文来源；首夜、其他夜、进场、明确领域事件与延迟效果按优先级、席位顺序和稳定 ID 自动排队，未完成队首或裁量任务会阻塞阶段推进。
- 受信能力处理器只读取冻结状态与严格输入，返回白名单语义事件、持续/延迟效果和至多一个结构化裁量任务。醉酒/中毒抑制确定性效果但仍消费限次尝试；角色变化终止旧实例来源记录，死亡/复活只暂停和恢复仍属于当前实例的效果。
- 裁量任务只保存固定来源、合法候选、结果 Schema、因果触发和 `storyteller-only` 可见性；只有 Host/System 能解决或取消。当前参与者视图尚未接入真实能力状态，完整任务不能广播后再过滤。

具体角色对提名资格、投票权重、门槛、处决、保护、特殊胜负和胜负阻止的修改属于 M1-R7 至 M1-R11。M1-R6 只提供通用执行框架，不接受可由调用方覆盖票数、门槛、候选、胜负或死亡的参数；活动投票中的角色插入时序必须由后续包以明确语义事件演进。

## 权限视图

状态不能先完整广播再由客户端隐藏。当前已实现独立的参与者视图协议 `0.2.0`，模块不依赖 Vue、Vuex、WebSocket、DOM、Node 专用 API 或 LLM。视图源公开每席生死与死亡票状态，并为提名、投票、候选和流放领域事件提供正向投影；但领域状态仍不具备构造完整视图源所需的具体角色、认知和规则信息。后续需求必须在房主可信边界内把完整权威状态适配成严格只读的 `ParticipantViewSource`，组件、远端客户端与 Agent 不得直接构造该源。

视图源使用白名单字段分别表达公开对局、席位真相、席位认知、规则信息、合法动作、动作历史、裁量任务与领域审计。玩家自由私聊、AI 私有笔记、Prompt、模型请求与返回、Provider 凭据和设备私密数据不进入该源，也不存在可由调用方指定受众的通用负载容器。Schema 之外字段、重复标识或顺序、失效席位引用和未知记录类型全部失败关闭。

服务只公开 `createSnapshot(source, credential)` 与 `projectEvent(source, event, credential)`。主体由注入的可信解析器从凭证解析，且唯一决定视图类型：

- `StorytellerView`：全部席位真相与认知、规则状态、已投递规则信息、合法动作、动作历史、裁量任务和领域审计；不包含玩家自由私聊、Agent 私有运行时数据或凭据。
- `SeatView`：公共数据加凭证绑定席位的认知角色/阵营、已知状态、已投递信息、合法动作和动作历史；不提供目标席位覆盖参数，也不单列真实角色或真实阵营。
- `PublicView`：规则集、公开状态和阶段、公开特殊规则、席位显示资料与控制者类型，以及公开公告、消息、提名和投票记录。
- `ObserverView`：先生成 `PublicView`，再按策略关闭公开消息、逐票明细和历史记录；任何策略组合都只能删除数据。

人类和 AI 控制同一席位时经过相同的 `seat` 主体与 `SeatView`。AI 玩家即使与说书人运行在同一进程，也不能取得真相源；上下文构建函数不得接受完整状态后依靠 Prompt 约束模型“不要看”。

领域事件投影使用按源类型注册的专用投影器和输出负载 Schema。可见视图事件只保留目标所需语义，不携带权威事件 ID、权威序号、因果命令 ID、执行者、规则来源或记录时间；Observer 关闭逐票明细时，单席投票/支持返回 `null`，投票与流放结果删除席位列表但保留真实总数、门槛、候选和结果。未知类型或投影失败只形成房主侧结构化错误。面向远端的连续视图序号与重连游标仍由后续在线协议定义，不能直接复用权威序号。

所有快照和事件结果从允许字段正向构造，经目标 Schema 校验后深复制、深冻结并稳定排序。固定测试夹具覆盖真相与认知不一致、未知醉酒/中毒、跨席位私密信息、控制者等价、全部旁观策略组合、递归禁止键/唯一敏感值扫描和固定种子变形；`src/domain/views/` 使用独立覆盖率门禁。当前模块尚未接入真实权威状态、UI、WebSocket 或 Agent Runtime。

## 规则内核

当前已实现准备、首夜/昼夜循环、基础生死、复活、提名投票、旅行者流放、常规处决/胜负，以及版本化角色能力执行框架。规则内核最终还负责以下全部确定性部分：

- 开局人数与角色类型比例、设置修正和合法剧本校验。
- 阶段状态机、首夜/其他夜顺序和待行动者。
- 存活、死亡、处决、复活、醉酒、中毒和角色/阵营变化。
- 提名资格、投票资格、死亡票、计票、旅行者流放和处决限制。
- 持续效果的建立、暂停、终止和来源追踪。
- 通用及可确定的角色特殊胜负条件。
- 命令权限、幂等、状态不变量和事件重放。

对于信息真假、模糊注册、角色能力开放式选择和官方规则明确交给说书人判断的情况，当前框架已能生成带固定来源、合法候选和结果 Schema 的结构化裁量任务。M1-R7 至 M1-R11 为具体角色注册构造与解决处理器；未来 LLM 只能选择该任务允许的结果，不能自由发明状态变更。

## Agent Runtime 与 Skills

Runtime 面向说书人和玩家提供同一生命周期：

1. 从权限视图与新事件形成观察。
2. 选择与当前阶段匹配的系统提示词和 Skills。
3. 按预算调用 Provider，解析结构化回复或工具调用。
4. 校验 Skill 和工具权限，提交领域命令或通信命令。
5. 把结果、错误和规则拒绝反馈给 Agent，直到完成、超时或等待外部输入。

Skill 是可版本化、可测试的能力包，至少包含说明、允许工具、输入输出约束、示例和适用阶段。系统提示词负责身份、目标、风格与总体策略，不承载会频繁更新的全部规则正文。

每个 Agent 运行实例具有独立的：

- 消息历史与摘要
- 私有笔记命名空间
- 模型和预算配置
- 任务队列与取消信号
- 工具能力集合
- 审计 ID 与用量统计

## LLM Provider 适配

核心接口屏蔽供应商差异，并标准化：

- 消息与多模态输入的能力声明
- 普通和流式生成
- 原生工具调用或结构化输出降级
- AbortSignal 取消、超时、限流重试和退避
- 上下文窗口、Token 预算、费用与缓存命中
- 鉴权、CORS、网络和供应商错误分类

OpenAI、Claude、DeepSeek、火山方舟和 OpenAI 兼容本地模型分别实现 Adapter。供应商不支持原生工具调用时，可以由统一结构化协议降级，但必须经过同样的工具校验。

密钥存储与对局持久化分离。默认不把密钥写入 localStorage；如产品允许设备保存，应使用明确授权和浏览器安全存储方案，并提供一键清除。

## 在线会话

当前 townsquare WebSocket 服务是消息中继，房主是会话权威。重构后在线协议应区分：

- 权限过滤后的状态快照和领域事件
- 公开/私密通信
- 玩家动作请求与房主确认结果
- 心跳、能力协商、版本和重连游标

AI 玩家不建立远端 WebSocket 连接，而是通过房主浏览器内的本地传输实现同一客户端协议。这样可以复用动作、消息和重连语义，同时避免模拟多个网络客户端。

当前开发边界已经移除源码中的隐式公共中继：开发页面默认只连接 `127.0.0.1` 上的本地中继，生产构建必须显式配置受控地址，缺少或配置非法时关闭在线会话。该配置边界只防止开发误连外部生产服务，不替代后续的协议版本、权限过滤、隐私和正式部署设计。

协议消息必须具有版本、消息 ID、对局 ID、发送者、目标和幂等键。服务端只能看到完成中继所需的数据；端到端私密消息是否加密需在独立需求中澄清并设计。

## 规则知识流水线

规则同步是开发/构建工具，不在对局中实时抓取网页。流水线包含：

1. 读取版本化来源清单，只接受允许 HTTPS 域名、固定修订和原始 Wikitext SHA-256 完整的显式来源；正文新链接去重后作为候选报告，不自动扩抓。
2. 分别获取固定修订 HTML 与 MediaWiki API Wikitext，用后者校验修订、页面时间和内容哈希；使用 DOM 解析器定位 HTML 正文与页面身份，不使用难以维护的整页正则。
3. 清洗脚本、样式、表单、事件属性、目录、导航和无关展示，保留标题、段落、强调、嵌套列表、定义列表、表格、代码、引用、同源图片与安全引用。
4. 规范化 MediaWiki URL、锚点和稳定来源 ID 文件名；已生成页面改写为本地引用，清单内未生成页面保留固定在线修订，其他正文页进入候选报告；检测跨域重定向、危险协议、特殊命名空间与重复内容。
5. 以带版本 Schema 的格式输出 Markdown、逐页元数据、成功清单和 JSON/Markdown 抓取报告。逐页元数据同时记录 Wikitext、HTML 和 Markdown 哈希及 `untrusted-external-content` 可信边界。
6. 切分、索引并生成浏览器可加载的版本化知识包。
7. 以固定页面样本进行解析回归，以规则查询样本验证召回与引用。

同步器使用显式 User-Agent、串行最小请求间隔、请求超时、响应体上限、限量退避重试和 AbortSignal 取消。输出先写入工具所有的临时目录再原子发布，不覆盖无所有权标记的目录；已有成功输出时，失败重跑只把诊断发布到旁路目录。自动测试使用虚构 HTML/API 固定样本和假 HTTP，不访问真实站点；显式现场巡检产物只进入 `.work/`。

主要来源为集石运营维护的《染·钟楼谜团》中文官方资料站 `clocktower-wiki.gstonegames.com`。中文资料缺失时使用 `wiki.bloodontheclocktower.com` 等英文官方资料补充；补充内容需要翻译为中文，并在来源清单中同时记录英文页面修订、内容哈希、中文翻译版本和复核状态。中英文资料发生语义冲突时无条件采用中文官方结论，英文差异仅进入同步报告。集石中文官方魔典用于核对中文术语、界面信息架构和交互，不作为确定性规则正文的唯一来源。相邻实验项目的 Wiki 抓取逻辑只作为页面分类、正文提取、链接归一化和 Markdown 落盘需求的参考，不直接复制实现。现场正文与图片是否提交或发布必须先独立确认来源许可、体积和更新策略。

## 持久化与恢复

浏览器本地保存内容分为：

- 可恢复对局检查点与事件日志
- 房主设置和无敏感模型配置
- 每个 AI 玩家隔离的私有笔记
- 规则知识包与索引缓存
- 可选的 Agent 审计与用量数据

数据结构必须版本化并提供迁移。恢复对局时先验证事件链、规则版本和状态不变量；无法安全恢复则以只读方式导出诊断，不猜测修复隐藏状态。

## 测试架构

当前基础设施使用 Jest、Vue Test Utils v1 和 Vue CLI 转换链承载单元、Vue 组件、场景与本地中继集成测试，使用 Playwright Chromium 承载浏览器端到端测试。Node.js 22、锁文件安装、分层 npm 脚本和 GitHub Actions 组成一致门禁；测试启动只监听回环地址的本地中继并阻断外部网络，不把公共会话、真实 LLM 或生产数据作为依赖。初始源码不设置全仓覆盖率阈值，后续新模块在各自需求中定义有效覆盖和模块级门禁。

- 纯函数单元测试：规则、命令校验、归约器、视图过滤、知识清洗。
- 场景测试：使用给定初态和命令序列断言事件与最终状态，规则来源写入用例元数据。
- 属性测试：随机合法命令序列下验证状态不变量和重放一致性。
- Provider 契约测试：以假服务验证流式、取消、工具、限流和错误映射。
- Agent 测试：确定性假模型输出固定工具调用，验证权限、循环和失败恢复。
- 在线集成测试：房主、多个远端人类客户端和本地 AI 客户端使用相同协议。
- 浏览器端到端：完整昼夜、提名投票、断线恢复、人工接管和复盘。

## 演进约束

- townsquare 初始源码固定且不再主动同步，不补建全量旧行为基线；新增边界先写测试，修改遗留行为时为受影响范围增加回归。
- AI 能力通过新边界接入，不在 Vue 组件中直接调用模型。
- 每次只迁移一个可验收的垂直切片，保持魔典可构建、可运行。
- 训练与自博弈复用生产规则内核和事件格式，但运行在独立模拟入口，不能引入只为训练存在的规则捷径。
