# M1-R2 领域状态与事件协议

## 元信息

- 状态：本地完成
- 创建日期：2026-07-17
- 关联里程碑：[M1-R2 领域状态与事件协议](../milestone/roadmap.md#m1规则内核事件模型与权限视图)
- 负责人：Codex

## 背景与问题

M1-R1 已冻结首期中文规则范围、来源优先级和不可变版本策略，但当前 townsquare 仍由 Vue 组件、Vuex mutation 和 WebSocket 消息共同维护对局状态。遗留状态没有统一的领域命令、可重放事件、并发版本或幂等约束，后续权限视图、阶段内核、提名投票和角色能力若直接在该结构上继续扩展，将无法保证同一动作只结算一次、历史对局按原规则版本恢复，也无法证明 UI、同步与 Agent 消费的是同一语义。

M1-R2 需要先建立独立于 Vue、Vuex、WebSocket 和 LLM 的确定性协议底座。该底座只表达权威状态、命令处理、事件提交、幂等结果和重放，不提前实现 M1-R3 至 M1-R12 的权限过滤与具体游戏规则，也不允许提供绕开规则处理器的通用状态修改入口。

## 目标与成功标准

- 定义可版本化、可严格校验的权威状态、命令、事件、命令回执和事件日志格式。
- 建立纯函数事件归约与确定性重放，使同一初始条件和事件序列得到结构相同的状态。
- 建立命令 ID、状态修订和幂等语义，使重试不会重复提交事件，并能识别同一 ID 被用于不同命令的冲突。
- 将 M1-R1 的范围清单 ID、精确版本、规范语言、来源清单版本和完整性哈希固定到对局身份中。
- 为后续需求提供按命令类型、事件类型注册处理器和归约器的受控扩展点，不允许直接修改状态。
- 对未知版本、未知类型、无效序列、修订冲突、损坏日志和不一致回放全部失败关闭，并返回稳定的中文错误语义。
- 新模块具有有效单元与场景测试，现有 UI、Vuex、会话中继和生产构建保持不变。

## 用户与使用场景

- 后续房主 UI、AI 说书人 Skill 和远端玩家动作适配层把意图提交为同一种命令，而不是直接修改 Vuex。
- 规则内核校验命令后提交不可变领域事件；UI、在线同步、权限视图、Agent 观察和审计在后续需求中消费这些事件。
- 网络重试、按钮重复点击或断线重发携带同一命令 ID 时，只返回首次处理结果，不再次结算。
- 开发者可导出版本化事件日志并在无 UI、无网络、无 LLM 条件下重放，验证最终状态、修订和命令回执一致。
- 无法识别或无法安全重放的日志停止可写恢复并给出诊断，不使用当前代码猜测旧语义。

## 已确认需求

- M1-R2 只建设领域协议和执行基础设施，不把遗留 Vuex、组件或 WebSocket 迁移到新协议；UI 接入属于 M1-R12，权限投影属于 M1-R3，具体阶段、提名投票和角色能力分别属于后续 M1 需求。
- 新协议在房主浏览器中运行，不连接公共会话服务，不调用真实 LLM，不读取生产数据。
- 规则版本是对局身份的必填事实。M1-R1 的 `m1.zh-cn`、精确版本、`zh-CN`、来源清单版本和完整性哈希必须作为一个整体固定，不能只保存可变别名。
- 状态只能由已注册事件的纯函数归约器产生；命令处理器可以读取当前状态并返回候选事件，但不能直接修改状态或提交任意补丁。
- 命令和事件使用稳定 ASCII 类型标识；面向用户的诊断、测试描述和文档使用中文。
- 事件日志是房主侧权威真相数据，M1-R3 完成前不得直接广播或作为玩家/AI 上下文；API Key、Provider 凭据、完整 Prompt、AI 私有笔记和真实玩家私聊不得进入本协议。
- 归约器不能读取当前时间、随机数、网络、DOM 或浏览器存储；所有影响结果的 ID、时间与随机种子必须已存在于命令上下文或事件负载中。
- 事件提交采用先完整校验和试归约、再整体追加的原子语义；同一命令产生多个事件时不得只提交前半部分。
- 事件顺序由每局从 1 开始连续递增的 `sequence` 表达；状态 `revision` 等于最后提交的序号，空流为 0。
- 对未知协议版本、未知事件类型、重复或跳跃序号、对局 ID 不一致、规则集身份不一致和事件 Schema 不通过的日志拒绝重放。
- 初始版本不承诺跨主版本自动迁移。未来需要改变既有状态或事件语义时必须增加显式迁移器和旧版本回放用例，不允许原地改写历史事件。
- 规则集身份的 `id` 直接取冻结清单的 `manifestId`，当前值为 `botc-ai.m1-ruleset-scope`；不得使用文档占位名或另造一个未被 M1-R1 固定的 ID。
- 只实现最小核心状态：协议版本、对局 ID、固定规则集身份、随机种子、修订和生命周期占位；席位、效果、流程、通信、Agent 等结构由对应后续需求以版本化事件扩展，不在 M1-R2 预先冻结空字段全集。
- M1-R2 提供唯一的最小业务初始化动作 `game.create` 和事件 `game.created`，用于证明规则集固定、幂等、原子提交和从空流重放；不提供改阶段、加座位、改角色、改存活等具体游戏命令。
- 每个状态相关命令必须携带 `expectedRevision`。幂等查询先于修订校验：同一命令重试即使当前修订已前进，也返回首次结果；新的命令若修订过期则拒绝。
- 对通过信封校验的命令，无论成功还是被领域规则拒绝，都生成可持久化命令回执；相同命令 ID 与相同规范化内容返回原回执，相同 ID 对应不同内容则报幂等冲突。连信封都不合法的输入不占用命令 ID。
- M1-R2 定义完整事件流导入/导出与从零重放，不实现 IndexedDB、自动存档、增量检查点或崩溃恢复；这些持久化能力留给 M5-R4。状态快照只作为运行结果和测试断言，不能替代事件流成为权威来源。
- 初始实现沿用仓库 JavaScript 技术栈，使用 ES 模块、JSDoc、严格 JSON Schema 和运行时校验，不为该需求单独迁移 TypeScript。
- 初始协议版本使用 `0.1.0`，采用 SemVer；持久化信封显式保存格式版本。M1 全量规则完成不自动把协议升级为 `1.0.0`，协议稳定性与规则包版本分别管理。
- M1-R2 使用连续序号、严格 Schema、规则集身份和重放终态校验发现损坏；加密哈希链、签名与防篡改导出不属于本次范围，后续安全或持久化需求另行设计。

## 范围

- 新建独立的领域协议模块，不依赖 Vue、Vuex、WebSocket、DOM、Node 专用 API 或 LLM SDK。
- 定义严格的状态、命令、事件、命令回执、事件批次和事件流导出格式及其运行时校验。
- 定义稳定错误代码、中文错误信息和结构化错误详情，至少覆盖格式、版本、类型、修订、幂等、序列、规则集身份、处理器和归约器错误。
- 实现处理器与归约器注册表、命令分派、候选事件试归约、原子提交、回执缓存和事件流导入/导出。
- 实现 M1-R1 规则集身份加载与完整字段固定，不把范围清单误当作已实现的角色规则包。
- 实现最小初始化命令和事件，以及供后续需求扩展的受控 API。
- 提供协议 Schema、单元测试、场景测试、文档示例和模块公开入口。
- 同步产品、架构和路线图中的当前实现状态及后续依赖边界。

## 非范围

- 不实现 Storyteller/Public/Seat/Observer 权限视图，也不把权威事件裁剪为网络事件。
- 不实现座位分配、阶段推进、昼夜、死亡、处决、胜负、提名投票、旅行者、传奇/奇遇角色或任何角色能力。
- 不让 UI、Vuex、WebSocket、现有浏览器存储或本地会话中继使用新协议。
- 不实现跨标签页、多房主或服务端并发协调；单个房主浏览器内的乐观修订是本次并发边界。
- 不实现自动存档、IndexedDB、检查点压缩、崩溃恢复、跨版本数据迁移、签名或防篡改证明。
- 不新增 Agent、Prompt、Skill、Provider 或真实模型契约。
- 不修改线上环境、外部 Wiki、生产配置或真实对局数据，不 Push、不创建 PR、不部署。

## 规则与裁量边界

- M1-R2 不判定具体游戏规则，也不产生说书人裁量任务。
- 初始化只验证对局引用的规则集身份是本地明确允许且完整的固定描述，不据此宣称 110 个角色能力已经实现。
- 后续确定性规则必须通过已注册命令处理器与事件归约器接入；需要说书人裁量的行为由后续规则需求产生结构化任务，不能通过通用事件或状态补丁绕过。
- 规则来源继续遵循 M1-R1：中文官方资料优先、英文仅补缺且不得覆盖中文冲突；M1-R2 本身不抓取或解释规则正文。

## 交互与失败恢复

### 正常命令流程

1. 调用方构造包含协议版本、命令 ID、对局 ID、预期修订、执行者、命令类型和负载的命令。
2. 命令总线先校验信封与对应负载 Schema，再执行幂等查询和修订检查。
3. 已注册处理器读取只读状态并返回零个或多个候选事件，或返回结构化领域拒绝。
4. 总线为候选事件补齐序号、事件 ID、命令因果 ID、记录时间和规则集身份，在临时状态上依次严格归约。
5. 全部事件和最终不变量通过后，一次性提交事件、状态和命令回执。
6. 调用方收到稳定结果对象；后续 UI、同步和 Agent 适配层消费方式不在本需求实现。

### 重试、冲突与损坏恢复

- 相同命令重试返回首次回执，不再次运行处理器或生成新事件。
- 同一命令 ID 携带不同规范化内容时拒绝，并明确提示 ID 冲突。
- 新命令的 `expectedRevision` 与当前状态不一致时拒绝，调用方必须先读取最新状态再决定是否重试；协议层不自动合并意图。
- 处理器抛错、生成无效事件、归约器抛错或最终不变量失败时整批回滚，不留下事件、状态或成功回执。
- 导入日志任一条验证失败时停止在错误位置，返回只读诊断；不得跳过未知事件或继续生成可写状态。
- 本模块是同步确定性执行，不存在网络超时；调用方取消、异步任务和断线恢复由后续接入需求定义。

## 状态、事件与权限

### 状态

核心状态至少包含：

- `schemaVersion`：状态结构版本。
- `gameId`：稳定对局 ID。
- `ruleset`：规则集 ID、精确版本、规范语言、来源清单版本和完整性哈希。
- `seed`：不透明的固定随机种子，不在归约器内临时生成。
- `revision`：最后提交事件序号。
- `lifecycle`：只表达协议层是否已初始化；具体准备、昼夜和结束阶段由 M1-R4 定义。

状态对象和事件负载必须由归约器新建，不暴露可修改内部引用。具体不可变实现方式在测试中以“外部修改返回值不影响内部状态”和“处理器不能修改输入状态”验收。

### 命令

命令信封固定包含协议版本、命令 ID、对局 ID、预期修订、执行者引用、类型和负载。执行者只用于因果追踪；M1-R3 之前不把“字段格式合法”误当作“具有执行权限”。

### 事件

事件信封固定包含协议版本、事件 ID、对局 ID、连续序号、事件类型、因果命令 ID、执行者引用、记录时间、规则集身份和负载。事件一经提交不可修改；归约器只依赖事件内容和前一状态。

### 命令回执与事件流

命令回执保存命令 ID、规范化内容摘要、处理前后修订、结果状态、结构化拒绝或提交的事件 ID。事件流导出保存格式版本、对局身份、事件数组和持久化回执；导入后必须能重建相同状态与幂等结果。

### 权限与可见性

- 权威状态、完整事件流和领域拒绝可能包含后续加入的隐藏真相，只能留在房主侧。
- M1-R2 不提供面向玩家的序列化入口。M1-R3 必须从权威状态与事件生成最小权限视图，不能让调用方先拿完整对象再自行删字段。
- 初始事件不得包含密钥、Prompt、AI 私有记忆、浏览器存储内容或真实玩家通信正文。

## Agent、Skill 与 LLM 约束

- 本需求不新增或运行 Agent、系统提示词、Skills、工具或 LLM Provider。
- 命令协议为后续人类 UI 和 Agent Skill 共用，但任何 Agent 能执行的命令仍需 M1-R3 权限层和具体规则处理器共同校验。
- 超时、限流、Token 成本、流式输出和 Provider 降级不适用。
- 测试不得调用真实模型或外部网络。

## 兼容、迁移与回滚

- 新模块与遗留 Vuex、WebSocket 和浏览器存储并行存在，本需求不读取、迁移或覆盖任何存量对局。
- 初始协议只保证相同精确版本内的导出与重放。无法识别的主版本拒绝导入，不能静默套用当前 Schema。
- 同一版本的事件和状态 Schema 一经作为持久化格式使用不得原地改变语义；兼容新增需要明确策略，不兼容变化需要新版本和显式迁移器。
- 回滚代码时，旧代码只能写入其完整支持的协议版本；遇到新格式日志只能提供诊断，不能部分解释后继续写入。
- 本需求本地回滚只需撤销新增模块和文档，因为尚未接入 UI 或存量数据。

## 验收标准

- Spec 中影响实现的待确认项已清零，协议边界与 M1-R3、M1-R4、M1-R5、M1-R6、M1-R12、M5-R4 无冲突。
- 严格 Schema 拒绝未知字段、未知版本、非法 ID、无效时间、非法修订和不匹配的命令/事件负载。
- `game.create` 成功后固定完整 M1-R1 规则集身份；使用同一命令重试不增加事件，复用命令 ID 发送不同内容被拒绝。
- 新命令携带过期修订时被拒绝；同一命令的幂等重试不受后来修订前进影响。
- 处理器生成多个事件时全部成功或全部不提交；失败后状态、修订、事件数和回执保持一致。
- 完整事件流导出后可在新实例从零重放，得到结构相同的状态、连续修订和幂等回执。
- 篡改序号、对局 ID、规则集身份、事件类型、负载或格式版本会在确定位置失败关闭。
- 外部代码无法通过修改命令、返回状态、返回事件或导出对象的引用改变内部权威状态。
- 新模块不依赖 Vue、Vuex、WebSocket、DOM、Node 专用 API 或真实网络，可在 Jest 与浏览器构建中工作。
- `npm run test:coverage` 与 `npm run test:ci` 通过；Lint 警告不超过当前预算，最终差异只有 M1-R2 文件并创建本地提交，不 Push。

## 测试方案

- 单元测试：Schema 正反例、注册表重复/未知类型、初始化、规则集固定、修订、幂等、ID 冲突、批次原子性、不可变返回值和稳定错误语义。
- 归约测试：同一事件在相同前态产生相同后态；归约器不读取环境；非法前态或事件不能部分修改输入。
- 重放测试：空流、单事件、多事件、导出导入、重复/跳跃序号、交叉对局、未知版本、未知类型、无效负载和终态一致性。
- 场景测试：创建对局、重复提交、并发修订冲突、失败后重试、导出到新实例重放、重放后再次幂等提交。
- 属性式循环测试：使用固定种子构造多组合法事件序列，验证连续修订、重放一致和导出对象修改不影响内部状态；不新增真实网络或随机不稳定依赖。
- 集成测试：本需求未接入 Vuex、WebSocket 或持久化，不增加跨模块集成用例。
- 组件与端到端：没有用户界面变化，不新增专用用例；完整 `test:ci` 继续验证现有页面和本地会话无回归。
- 文档一致性：核对产品、架构、路线图和 M1-R1 对规则版本、权威状态、权限视图与持久化边界的描述。

## 实现计划

1. 先增加失败的单元与场景测试，覆盖严格 Schema、规则集身份、命令分派、幂等、乐观修订、批次原子性、不可变边界、导出与重放。
2. 实现浏览器兼容的规范化 JSON、SHA-256 命令指纹、结构化错误、协议注册表和 M1 规则集身份读取。
3. 实现 `game.create` / `game.created`、命令总线、事件归约、持久化回执以及事件流导入导出。
4. 执行针对性测试并修正，再同步产品、架构和路线图。
5. 执行覆盖率和完整 `test:ci`，检查差异后创建本地提交，不 Push。

## 风险与待确认项

- 当前没有影响实现的待确认项。
- 领域事件格式一旦被后续需求和存档引用，调整成本较高，因此初始实现必须保持最小、严格和可显式演进，避免提前冻结尚未澄清的角色或 UI 字段。
- M1-R1 清单版本 `0.2.0` 是范围快照，不是可运行规则包。初始化事件必须准确表达这一事实，防止后续界面把“身份已固定”显示为“全部规则已实现”。
