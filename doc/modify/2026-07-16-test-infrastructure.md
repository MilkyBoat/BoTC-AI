# 本项目测试基础设施

## 元信息

- 状态：本地完成
- 创建日期：2026-07-16
- 关联里程碑：[M0-R3 本项目测试基础设施](../milestone/roadmap.md#m0固定源码基线与开发治理)
- 负责人：Codex

## 背景与问题

项目当前保留了 townsquare 的 Vue 2.7.15、Vue CLI 5 和 WebSocket 中继源码，但没有单元、组件、场景或端到端测试入口。现有 GitHub Actions 仍使用 Node.js 14 和 `npm install`，只执行会被 416 条遗留警告阻断的严格 Lint；本地基线只能执行构建，后续规则内核、权限视图和浏览器 Agent Runtime 缺少可复用的测试承载方式。

M0-R2“上游行为基线”已明确跳过。townsquare 源码作为固定初始快照保留，未来不主动获取或合并上游更新。因此 M0-R3 不补建旧项目的全量行为清单，也不以未来同步上游为目标；它只建立可运行、可扩展且默认离线的测试基础设施，并用少量代表性用例证明每一层入口有效。后续新功能必须按需求增加测试，修改遗留行为时再为受影响范围补回归。

## 目标与成功标准

- 开发者能通过稳定的 npm 脚本分别运行单元测试、Vue 组件测试、场景测试、端到端测试和覆盖率检查。
- 一条本地总入口能以确定性方式完成单元、组件、场景、端到端、Lint 和生产构建验证。
- GitHub Actions 在受支持的 Node.js 版本上使用锁文件安装依赖，执行与本地一致的门禁，不连接 `clocktower.online` 或其他外部生产服务。
- 每类测试至少有一个基于现有真实代码或真实页面的代表性用例，能够在被测行为破坏时失败；不创建只断言测试框架自身可运行的空样例。
- 测试失败保留可读日志；端到端失败在 CI 上传报告，成功时不长期保存无用产物。
- 路线图、开发约定、README 和上游来源说明不再要求主动跟踪 townsquare。

## 用户与使用场景

本需求服务于本项目开发者和代码评审者。开发者在本地修改代码后按层运行快速测试，在提交前运行总门禁；GitHub Actions 在开发分支 Push 或面向 `develop`、`main` 的 Pull Request 上重复执行相同验证。

本需求不改变房主、玩家、AI 说书人、AI 玩家或旁观者的产品交互，也不新增线上运行入口。

## 已确认需求

- M0-R2 保留编号但标记为“已跳过”，不重新编号后续需求；M0-R3 直接依赖 M0-R1。
- 不建立旧 townsquare 的全量行为基线。M0-R3 只增加足以证明各测试层真实有效的代表性用例。
- townsquare 固定快照、GPL-3.0 许可证、原作者归属和导入提交继续保留，主动上游同步流程、跟踪要求和相关远端不再作为项目治理的一部分。
- 测试默认使用本地确定性状态、假实现和本地开发服务器，禁止调用真实付费 LLM、外部会话服务或生产数据。
- 单元、组件和场景测试共用 Jest 执行基础；Vue 单文件组件使用与 Vue 2 兼容的 Vue Test Utils v1 和 Vue CLI Jest 转换链。端到端测试使用 Playwright。
- 单元测试验证纯逻辑或 Vuex 模块输入输出；组件测试验证可观察 DOM、事件和交互，不绑定私有实现细节；场景测试以给定初态和动作序列验证跨模块结果；端到端测试从用户可见页面和交互验证应用启动。
- 测试代码统一放在 `tests/unit/`、`tests/component/`、`tests/scenario/` 和 `tests/e2e/`，共享的固定数据、假实现和辅助函数放在 `tests/fixtures/`、`tests/fakes/` 和 `tests/helpers/` 中按需创建。
- 端到端测试由 Playwright 启动本地 Vue 开发服务器，只运行 Chromium；跨 Firefox、WebKit 和移动设备矩阵留待产品浏览器基线需求确认。
- Node.js 22 是本地和 CI 的统一基线，通过仓库版本声明和 GitHub Actions 固定主版本；不把“任意当前 LTS”作为不可重放的门禁配置。
- 本需求调整测试相关 ESLint 配置后，遗留 Lint 警告基线为 415 条，不在本需求中批量修复。CI 只允许警告总量持平或下降，并继续阻断所有 Lint 错误和警告总量上升。
- 本需求生成覆盖率报告，但不对整个遗留源码设置百分比阈值；从本需求开始，新增或修改的可测试业务逻辑必须随需求提供有效测试。规则内核等新模块在对应需求中设置模块级覆盖率门禁。
- 现有手动 GitHub Pages 部署工作流不属于测试门禁，继续保持只能人工触发；自动部署仍禁止。

## 范围

- 增加 Vue CLI Jest、Vue Test Utils v1、Playwright 及其必要的测试依赖和锁文件变更。
- 增加 Jest、Playwright、覆盖率、路径别名、静态资源和样式处理所需的最小配置。
- 在 `package.json` 中增加分层测试、覆盖率和本地总门禁脚本，命令命名与职责写入 README。
- 分别增加至少一个真实的单元、组件、场景和 Chromium 端到端用例。
- 端到端用例显式拦截并拒绝对公共会话地址的请求或 WebSocket 连接，证明测试不会误连上游生产服务。
- 重写 GitHub Actions 测试工作流，使用 `npm ci`、Node.js 22、依赖缓存、Chromium 安装和串行稳定执行。
- 为 Lint 建立遗留警告预算，保证警告只能持平或下降；记录清理全部遗留警告的后续责任边界。
- 增加 Node.js 版本声明，更新 README 的本地安装、分层测试、完整验证和 CI 说明。
- 更新里程碑、产品质量状态、架构演进约束、开发约定和 townsquare 来源文档，使其与跳过 M0-R2、停止上游跟踪的决策一致。
- 删除仅服务于原上游协作流程且不再适用于本项目的自动 Changelog 检查；保留人工部署工作流。
- 移除本地 `upstream` Git 远端，但保留来源、导入提交和许可证记录。

## 非范围

- 不补齐魔典、角色分发、在线同步、提名或投票的全量遗留行为测试。
- 不实现规则内核、命令/事件协议、权限视图、Agent Runtime、Provider、Skills 或 Wiki 检索。
- 不启动 M0-R4，不修改公共会话地址的运行时配置方式，不把当前会话中继改造成产品级本地环境。
- 不批量格式化遗留源码，不在本需求内消除 415 条现有 Lint 警告。
- 不升级 Vue、Vue CLI、Vuex、WebSocket 协议或其他生产依赖；测试依赖引出的必要兼容修正必须最小化并单独说明。
- 不设置全仓覆盖率百分比，不把仅提高数字而缺少行为断言的用例视为有效覆盖。
- 不连接真实外部服务，不使用真实 API Key、Cookie、证书、玩家私聊或对局数据。
- 不 Push、不创建 Pull Request、不触发工作流或部署。

## 规则与裁量边界

本需求不实现或修改桌游规则，官方规则版本、角色能力和说书人裁量均不适用。代表性测试只能固定当前代码已有的通用状态操作和页面启动行为，不应把尚未核对官方来源的旧实现细节提升为未来规则事实。

后续规则需求必须在场景用例元数据中记录规则来源和版本；本需求只预留目录、命名与辅助能力，不虚构规则样例。

## 交互与失败恢复

- 分层命令默认单次运行并以退出码表达成功或失败；开发者可显式使用 Jest 或 Playwright 的观察模式，但观察模式不进入 CI。
- 本地总门禁按快速测试、Lint、构建、端到端的顺序执行，任一步失败立即返回非零，不掩盖原始错误。
- Playwright 启动端口被占用或本地服务器未就绪时应明确失败，不回退到线上地址。
- 端到端测试超时后关闭浏览器与本地服务器；用户用 Ctrl-C 取消时不遗留后台进程。
- CI 中 Playwright 失败时上传 HTML 报告；测试成功、任务被取消或非端到端步骤失败时不要求生成报告。
- 测试产生的覆盖率、Playwright 报告、结果目录和临时文件必须被 Git 忽略，不进入提交。

## 状态、事件与权限

本需求不新增产品状态、命令、领域事件或持久化格式。测试固定数据必须使用虚构玩家、房间和消息，不包含真实隐藏身份或私密信息。

测试辅助函数按最小权限构造 Store 或组件，不为方便测试暴露生产真相接口。端到端只访问本地页面；任何到外部 HTTP、HTTPS、WebSocket 或 LLM 端点的意外访问都应失败。

## Agent、Skill 与 LLM 约束

本需求不运行 Agent、不新增 Skill、不接入 LLM，也不测试真实 Provider。后续 Agent 测试必须使用确定性假模型；该约束写入测试说明，但具体假 Provider 在 M2-R4 实现。

## 兼容、迁移与回滚

- 保持当前 Vue 2.7.15、Vue CLI 5、Vuex 3 和生产构建入口不变；测试工具适配现有构建栈，不引入 Vite 迁移。
- Node.js 22 作为开发和 CI 基线；锁文件由同一主版本 npm 重新生成并通过全新 `npm ci` 验证。
- 测试配置和测试文件不改变已有浏览器存储、在线协议或存量对局。
- 删除 `upstream` 远端只影响本地 Git 跟踪配置，不删除快照源码、提交历史、许可证或归属说明；如未来确需重新参考外部项目，必须创建新的独立需求并显式添加来源。
- 回滚本需求时可移除测试依赖、配置、用例和 CI 门禁并恢复脚本；不需要迁移产品数据。

## 验收标准与结果

本地验收使用 Node.js 22.17.1 和 npm 11.13.0 完成。`npm ci` 按锁文件完成干净安装；`npm run test:ci` 连续通过 2 个单元测试、2 个组件测试、1 个场景测试、415 条遗留警告预算、生产构建和 1 个 Chromium 端到端测试。`npm run test:coverage` 成功生成报告，当前全仓基线为语句 4.24%、分支 2.68%、函数 6.21%、行 4.17%，不作为本需求门禁阈值。GitHub Actions 因本需求不 Push 而只完成配置静态检查，未触发远端运行。

- `node --version` 的主版本为 22，`npm ci` 在干净依赖目录中成功。
- `npm run test:unit` 只执行单元测试并成功。
- `npm run test:component` 只执行 Vue 组件测试并成功。
- `npm run test:scenario` 只执行场景测试并成功。
- `npm run test:e2e` 自动启动本地页面，只用 Chromium 执行并成功，过程中没有访问公共会话或 LLM 服务。
- `npm run test:coverage` 生成覆盖率报告且不执行端到端测试。
- `npm run lint-ci` 对当前遗留警告成功，对任一新增警告或错误失败。
- `npm run test:ci` 在本地依次完成全部测试、Lint 和生产构建，退出码为 0。
- GitHub Actions 对 Push 到 `develop`、`main` 以及面向两者的 Pull Request 执行等价门禁，使用 Node.js 22 和 `npm ci`，不包含部署步骤。
- 每个测试目录至少有一个基于现有代码或页面的代表性用例；人为破坏其被测行为时对应测试会失败。
- `npm run build` 成功，`dist/index.html` 和静态资源存在。
- `git remote -v` 不再包含 `upstream`；来源文档仍能查到 `bra1n/townsquare`、导入提交、版本和 GPL-3.0 许可证。
- README、AGENTS、产品、架构、里程碑和来源文档对测试入口、M0-R2 状态及上游策略的描述一致。
- 最终差异不包含 `.work/`、覆盖率、Playwright 报告、浏览器二进制、生产构建产物或其他临时文件。
- 完成后创建一个仅包含本需求差异的本地提交，不 Push。

## 测试方案

- 单元测试：覆盖一个现有 Vuex 模块的纯状态变更和边界输入，证明模块可以独立加载和断言。
- 组件测试：挂载一个现有 Vue 单文件组件，从用户可观察的 DOM、点击或 `$emit` 验证输入输出，使用最少的全局 Stub。
- 场景测试：构造隔离 Store，以初态和多步提交验证一个不涉及官方规则判定的现有状态流程；用例标题明确这是基础设施烟雾场景，不宣称覆盖全部旧行为。
- 端到端测试：启动本地开发服务器，验证首页、版本标识和一个无外部依赖的基础交互；监听网络并拒绝公共会话地址。
- 门禁回归：分别执行各分层命令、覆盖率、Lint、生产构建和总入口；至少一次从清空 `node_modules` 后执行 `npm ci` 验证锁文件。
- 配置负向检查：临时制造测试失败和新增 Lint 警告，确认对应命令非零；检查结束后恢复临时改动。
- CI 静态检查：核对触发分支、Node.js 版本、`npm ci`、Chromium 安装、测试命令、报告上传条件和无部署步骤。未 Push 前不触发真实 GitHub Actions。
- 安全检查：搜索测试、配置、日志和 Git 差异，确认没有生产 URL 访问、密钥、证书、Cookie 或真实对局数据。

## 风险与待确认项

无影响实现的待确认项。旧 Vue CLI 与测试工具的兼容性、遗留 Lint 警告数量漂移以及端到端测试误连公共会话服务，已分别通过 Vue 2 官方兼容测试链、固定警告预算和阻断外部网络访问控制。

`npm ci` 仍会报告旧生产依赖链 `@achrinza/node-ipc@9.2.8` 未声明支持 Node.js 22，并报告 65 个依赖漏洞（18 个低危、25 个中危、20 个高危、2 个严重，包含开发依赖）。当前测试与构建均通过；本需求不执行可能破坏兼容性的 `npm audit fix --force`，依赖升级和漏洞治理必须作为独立需求处理。
