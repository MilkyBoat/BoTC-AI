- 状态：本地完成
- 创建日期：2026-07-17
- 关联里程碑：[M1-R3 参与者权限视图](../milestone/roadmap.md#m1规则内核事件模型与权限视图)

## 背景与问题

M1-R2 已建立房主浏览器中的权威状态、命令、事件、幂等回执和重放协议，但当前只提供房主侧完整状态与事件流，明确禁止直接发送给玩家或 Agent。后续阶段规则、投票、角色能力、在线同步与 Agent Runtime 都会产生真实角色、认知角色、阵营、醉酒/中毒、私密信息、合法动作、说书人裁量任务和系统审计等不同敏感度的数据。若调用方先取得完整对象再自行删除字段，任何遗漏、未知新增字段或序列化路径都可能泄露隐藏信息。

M1-R3 需要建立唯一的参与者投影入口。投影必须从房主侧受控数据源按请求主体生成最小快照，并为后续领域事件提供同样的失败关闭投影语义。人类和 AI 控制同一席位时必须得到完全相同的 `SeatView`；Prompt 约束、组件隐藏、CSS、客户端删字段和“模型不要看”都不能替代确定性权限代码。

M1-R2 当前权威状态没有席位与游戏规则字段。M1-R3 不应为了构造测试数据而提前实现 M1-R4 的席位生命周期、阶段状态机或角色分发，也不能在已冻结的协议 `0.1.0` 状态中加入任意可写扩展容器。因此本需求需要同时明确权限投影的数据源契约及其与后续权威状态的接入边界。

## 目标与成功标准

- 实现严格版本化的 `StorytellerView`、`PublicView`、`SeatView` 和 `ObserverView` 快照 Schema 与唯一投影入口。
- 请求主体只能获得其身份允许的视图；席位主体不能通过传入其他 `seatId` 读取他人视图。
- 说书人视图获得主持规则所需的对局真相、裁量任务和审计，但不获得 API Key、Provider 凭据、原始 Prompt/模型请求、AI 玩家私有笔记或其他设备私密数据。
- 席位视图只包含公开信息、该席位的认知身份、已收到的私密信息、自己的动作历史和当前合法动作；真实身份、隐藏阵营、未知状态与其他席位信息不因同进程运行而泄漏。
- 公开视图只包含规则允许公开的对局数据；旁观者视图只能从公开视图继续裁剪，不能通过策略增加字段。
- 为后续领域事件定义注册式、类型明确、失败关闭的投影接口；隐藏或未知事件不能把原始类型、负载、权威序号或事件存在性作为占位信息泄漏。
- 所有投影结果通过严格 Schema 校验、深复制和冻结；调用方无法借引用修改权威输入或其他视图。
- 以正向矩阵、负向字段搜索和变形测试证明真相字段、私密信息、内部 ID、凭据形态和跨席位数据不会进入错误视图。

## 用户与使用场景

- 房主或未来 AI 说书人读取 `StorytellerView`，主持需要完整真相，但模型凭据和 AI 玩家私有运行时数据仍在视图之外。
- 人类玩家与 AI 玩家都以席位主体请求自己的 `SeatView`，即使二者运行位置不同也获得相同字段语义。
- 未认领席位的页面、公开城镇广场和无需身份的规则展示使用 `PublicView`，不能先接收真相状态再由客户端隐藏。
- 经房主允许的旁观者使用 `ObserverView`；房主策略只能减少公开数据，例如隐藏实时交流或投票细节。
- 在线同步、断线恢复和 Agent 观察在后续接入时调用同一投影模块，不能各自维护一套字段过滤器。
- 新事件类型尚未实现投影时，系统停止向目标主体发布该事件并给房主侧返回诊断，而不是发送原始事件或猜测公共字段。

## 已确认需求

- M1-R3 只实现参与者权限视图、请求授权、投影契约和信息泄漏测试，不实现具体游戏规则、角色能力、席位增删命令或遗留 UI/WebSocket 接入。
- 权威状态和完整事件始终只存在于房主侧；远端客户端与 AI 上下文只能接收投影结果。
- 人类与 AI 使用同一种席位主体和 `SeatView`，不能因控制者类型不同获得额外真相字段。
- `StorytellerView`、`PublicView`、`SeatView`、`ObserverView` 使用稳定 ASCII 字段和类型 ID；面向用户的诊断、文档与测试描述使用中文。
- 投影是确定性同步纯函数，不读取网络、DOM、时间、随机数、浏览器存储或 LLM。
- 投影结果和输入之间不存在共享可变引用；一个视图的修改尝试不能影响权威源或其他主体视图。
- 未知主体、未知席位、主体与席位不匹配、未知视图版本、未知记录类型、无投影器事件和不合法策略全部失败关闭。
- API Key、Provider 凭据、Cookie、证书、原始系统提示词、完整模型请求/返回、AI 私有笔记和设备私密数据不属于参与者视图数据源，任何视图均不得包含。
- M1-R3 不连接或修改线上服务、生产配置和真实对局数据，不调用真实 LLM，不 Push、不创建 PR、不部署。
- M1-R3 新建独立的版本化 `ParticipantViewSource` 只读契约和固定测试夹具，不修改 M1-R2 `0.1.0` 权威状态或事件格式。后续 M1-R4 至 M1-R6 在扩展真实权威状态时，由房主侧受控适配器生成该数据源；组件、远端客户端和 Agent 不得自行构造。
- 视图请求主体独立于 M1-R2 的审计 `actor`：`storyteller`、`seat`、`public`、`observer` 四类。人类/AI 控制者不进入权限主体；席位主体在凭证中固定自己的 `seatId`，公开 API 不再接受可覆盖的目标席位参数。
- `StorytellerView` 包含规则集、公开状态、全部席位的真实/认知角色与阵营、规则状态、已投递私密规则信息、待裁量任务和领域审计；不包含玩家自由私聊正文、AI 私有笔记、模型 Prompt/请求/返回或任何凭据。说书人与玩家的规则交互可见，玩家之间私聊默认不进入说书人视图。
- `SeatView` 只暴露该席位的认知角色/阵营，不单列真实角色或真实阵营。即使真实值恰好相同，也只通过认知字段表达；醉酒、中毒、角色变化等未知事实只有在规则明确告知后，才以该席位收到的信息记录出现。
- `PublicView` 公开规则集、公开阶段、座位顺序、显示名、公开存活/死亡、公开角色、公开特殊规则、公告、提名和投票结果。席位由人类还是 AI 控制属于产品运行信息，默认公开；连接 ID、设备状态、私密动作、真实/认知角色和隐藏阵营不公开。
- `ObserverView` 必须从已经生成的 `PublicView` 继续投影。默认与公开信息相同但不包含任何交互能力；房主可用仅允许关闭的策略隐藏实时交流正文、逐票明细或完整公开历史，不能增加 `PublicView` 不存在的数据。
- M1-R3 同时实现快照与领域事件投影注册表。可见事件转换为不携带权威事件 ID、权威序号或因果命令 ID 的视图事件；完全隐藏的已知事件返回空投影，不向目标主体发送占位符；未知事件抛出只供房主处理的结构化错误。面向客户端的视图游标与连续序号留给后续在线协议需求。
- 视图源使用显式字段和按种类注册的规则信息记录，不提供任意 `payload + audience` 的通用旁路。新记录或事件种类必须先增加 Schema、投影器和各主体泄漏测试，未注册内容默认不可见。
- 初始视图协议版本使用独立的 `0.1.0`，与领域协议版本和规则包版本分别演进；不在本需求承诺旧视图跨主版本迁移。

## 范围

- 新建浏览器兼容的参与者视图模块，不依赖 Vue、Vuex、WebSocket、DOM、Node 专用 API 或 LLM SDK。
- 定义严格的视图源、请求主体、旁观者裁剪策略、四类快照和视图事件 Schema。
- 实现单一主体授权入口，分别生成 `StorytellerView`、`PublicView`、`SeatView` 和 `ObserverView`。
- 实现明确的席位真相、席位认知、公开状态、私密规则信息、合法动作、裁量任务和审计字段投影。
- 实现按类型注册的领域事件投影器与失败关闭诊断，不提供通用原始事件复制或删字段函数。
- 实现结果深复制、冻结、稳定排序和输入完整性检查。
- 提供固定虚构对局夹具，覆盖至少两个席位、真实/认知不一致、隐藏阵营、醉酒/中毒真相、点对点规则信息、公开信息、裁量任务、合法动作和审计数据，并验证自由私聊与凭据不属于视图源。
- 提供自动化信息泄漏矩阵、负向字段/值扫描、跨席位变形测试和未知类型回归。
- 同步产品、架构、路线图、文档索引和 M1-R3 验收记录。

## 非范围

- 不修改 M1-R2 领域协议版本、`game.create` / `game.created`、事件流或规则集身份。
- 不实现真实席位创建、角色分发、阶段推进、死亡、提名投票、胜负、旅行者、角色能力或说书人裁量流程。
- 不实现具体游戏命令的权限矩阵；本需求只授权“谁能请求哪种视图”，具体动作权限由对应规则处理器与后续权限需求共同完成。
- 不把遗留 Vuex 转换为新权威状态，不让现有组件或 WebSocket 使用新视图。
- 不实现在线客户端连续视图事件序号、重连游标、增量快照、缓存或远端传输加密。
- 不把聊天系统、Agent 私有笔记、Prompt、模型调用或 Provider 配置迁入领域状态。
- 不修改线上环境、外部 Wiki、生产服务、生产配置或真实玩家数据。

## 规则与裁量边界

- M1-R3 不判定具体游戏规则，只根据明确的源字段和主体身份执行信息可见性。
- “玩家知道什么”与“真实发生什么”必须分别建模。`SeatView` 使用认知字段和已投递信息，不通过比较真相字段动态猜测玩家是否应知。
- 醉酒、中毒、伪装、注册、角色/阵营变化和错误信息等未来规则不会自动改变投影权限；规则内核必须先产生该席位被允许知道的结构化认知或信息记录。
- 说书人裁量任务只进入 `StorytellerView`；裁量结果是否公开或发送给某席位，由后续规则事件产生明确的公开或席位信息记录。
- 权限模块不得根据 LLM 输出、Prompt 指令、聊天正文或外部 Wiki 内容提升可见性。

## 交互与失败恢复

### 正常快照流程

1. 房主侧受控代码提供通过 Schema 校验的 `ParticipantViewSource`。
2. 调用方提交固定的视图主体；席位主体的凭证中已包含唯一 `seatId`。
3. 投影器校验主体、席位存在性、源版本和旁观策略。
4. 投影器只从对应显式字段构造新对象，不先复制完整源再删除敏感字段。
5. 结果通过目标视图 Schema 和泄漏不变量校验后深度冻结并返回。

### 事件投影流程

1. 房主侧把单条已校验领域事件与目标主体交给注册表。
2. 注册表按事件类型选择专用投影器；投影器只返回该主体允许看到的视图事件字段。
3. 完全隐藏的事件返回空投影；未知类型或投影失败返回仅房主可见的结构化诊断，原始事件不进入结果。
4. 视图事件不携带权威事件 ID、序号、因果命令 ID 或其他可用于推断隐藏事件数量的元数据。

### 错误与恢复

- 未知或伪造主体、席位不存在、主体与目标不一致时拒绝，不回退 `PublicView` 或其他席位。
- 源 Schema 不通过、包含未知字段、重复席位、交叉引用失效或敏感数据出现在禁止位置时拒绝整个快照。
- 未知旁观策略字段或试图开启超出 `PublicView` 的能力时拒绝；策略不能默认为宽松模式。
- 新字段或事件没有投影定义时保持不可见并给房主诊断；修复后重新生成快照或事件投影，不缓存不完整结果。
- 投影是本地同步纯函数，不涉及超时、重试、断线或取消；在线恢复由后续协议处理。

## 状态、事件与权限

### 视图源

建议的只读视图源至少表达：

- 对局公开身份：规则集、对局显示状态和后续可公开阶段。
- 席位公共资料：稳定席位 ID、顺序、显示名、公开存活状态、公开角色及控制者展示类型。
- 席位真相：真实角色、真实阵营、规则状态、隐藏效果与说书人标记。
- 席位认知：认知角色、认知阵营、已经明确获知的状态与合法动作。
- 规则信息记录：公开公告、对指定席位投递的信息、说书人与席位规则交互。
- 公开流程记录：后续提名、投票、处决、流放及公开阶段历史。
- 说书人任务和领域审计：待裁量任务、规则拒绝、命令与事件摘要。

玩家自由私聊、AI 私有笔记和模型运行时数据不进入该源。后续真实权威状态接入时，视图源必须在房主可信边界内由确定性适配器产生。

### 视图主体

- `storyteller`：只能请求 `StorytellerView`。
- `seat`：主体固定唯一 `seatId`，只能请求自己的 `SeatView`。
- `public`：只能请求 `PublicView`，不携带身份或席位参数。
- `observer`：只能请求应用房主裁剪策略后的 `ObserverView`。

调用方不能把视图种类和目标席位作为两个可自由组合的参数；主体本身决定唯一视图类型。

### 视图事件

视图事件使用独立版本和类型 Schema，只保存目标视图需要的领域语义。投影注册表不能把原始领域事件展开后按键名黑名单过滤；每种领域事件必须显式构造各主体允许看到的视图事件。空投影与错误诊断只在房主进程内部存在，不序列化给目标主体。

## Agent、Skill 与 LLM 约束

- M1-R3 不新增 Agent、Prompt、Skill 或 Provider，也不调用真实 LLM。
- 后续 AI 说书人只能通过 `StorytellerView` 工具读取主持数据；AI 玩家只能通过与人类相同的 `SeatView` 工具读取席位数据。
- 上下文构建器必须接收投影结果，不能接收完整权威状态后依赖 Prompt 删除或忽略字段。
- Prompt 注入、聊天指令和规则知识内容不能改变主体身份、目标席位、旁观策略或事件投影器选择。
- 超时、限流、Token 成本和 Provider 降级在本需求不适用。

## 兼容、迁移与回滚

- M1-R3 新模块与 M1-R2 领域协议并行存在，不修改已完成的 `0.1.0` 状态、事件或重放文件。
- 当前没有真实参与者权威状态或存量视图数据，因此不迁移 Vuex、浏览器存储或在线协议。
- 视图 Schema 使用独立版本。破坏字段语义、主体权限或事件投影的变化必须发布新视图版本并增加旧版本泄漏回归；不能原地扩大旧主体可见范围。
- 后续接入真实权威状态时，适配器必须通过同一固定夹具和泄漏矩阵，证明接入没有改变视图语义。
- 回滚本需求只需停止使用新视图模块；由于尚未接入 UI、WebSocket 或持久化，不会改写存量数据。

## 验收标准

- Spec 中影响实现的待确认项已清零，且 M1-R3 与 M1-R2、M1-R4、M1-R5、M1-R6、M1-R12 的职责边界无冲突。
- 四类主体只能得到唯一对应视图；席位主体无法请求他人席位或升级为说书人视图。
- `StorytellerView` 包含主持所需真相、认知、规则信息、任务和审计，但不包含自由私聊、AI 私有运行时数据或凭据。
- `SeatView` 只含公开信息、自己认知、自己已收到的信息、自己动作与合法动作；测试夹具中的真实角色、隐藏阵营、未知醉酒/中毒状态、他人认知和他人信息全部不存在。
- `PublicView` 不含任何真实/认知身份、隐藏状态、私密信息、合法动作、内部连接 ID、任务或审计。
- `ObserverView` 是 `PublicView` 的严格子集或等价公开数据，任何策略组合都不能新增字段或值。
- 未知主体、席位、源字段、记录类型、事件类型和策略字段全部失败关闭，不回退原始对象或宽松视图。
- 完全隐藏事件不会返回占位、原始类型、权威序号、因果 ID 或能推断事件发生的结果；可见事件只包含专用视图 Schema 允许的字段。
- 对同一席位更换人类/AI 控制类型时，除公开控制展示字段外，`SeatView` 的规则信息和权限结果完全相同。
- 视图结果无共享可变引用，且模块公开 API 不暴露能跳过主体授权的底层投影器。
- 新模块独立 ESLint 为 0 错误、0 警告，并设置与逻辑风险匹配的模块级覆盖率门禁。
- `npm run test:coverage` 与 `npm run test:ci` 通过，最终差异只包含 M1-R3 文件并创建本地提交，不 Push。

## 测试方案

- Schema 单元测试：视图源、四类主体、旁观策略、四类快照和视图事件的正反例、未知字段、重复 ID、失效引用与错误版本。
- 主体授权矩阵：逐一验证每类主体的唯一视图、席位绑定、未知席位、伪造目标和权限升级失败。
- 字段泄漏矩阵：为每个敏感字段和值断言允许视图存在、禁止视图不存在，不只检查顶层键。
- 跨席位变形测试：交换两个席位真相、认知、私密信息和动作，只允许对应说书人/目标席位视图变化。
- 控制者等价测试：同一席位在人类与 AI 之间切换时，规则权限数据保持一致。
- 认知差异场景：真实角色/阵营与认知不一致、未知醉酒/中毒、错误信息、角色变化后未获知，确认 `SeatView` 不从真相推导。
- 旁观策略组合：遍历所有关闭项，证明结果始终是 `PublicView` 的数据子集。
- 事件投影测试：公开、说书人、单席位、完全隐藏和未知事件；禁止原始 ID、序号、因果命令与隐藏负载泄漏。
- 不可变与引用测试：修改输入、一个视图或投影事件不会影响权威源、缓存或其他视图。
- 模糊测试：以固定种子生成席位、信息和事件组合，扫描禁止键、唯一敏感值和跨席位标识。
- 集成、组件与端到端：本需求尚未接入领域引擎、UI 或 WebSocket，不增加专用集成/组件/E2E 用例；完整 `test:ci` 验证现有行为无回归。

## 实现与验收结果

- 新建 `src/domain/views/`，以独立协议 `0.1.0` 提供严格的视图源、主体、四类快照与视图事件 Schema。服务实例深冻结，只公开 `createSnapshot` 与 `projectEvent`；主体必须由注入的可信解析器从凭证解析。
- 快照从允许字段正向构造。`SeatView` 只读取认知与本席位信息，`ObserverView` 先生成 `PublicView` 再删除，`StorytellerView` 也不接收聊天、Agent 运行时或凭据字段。源与结果均执行重复 ID/顺序、席位交叉引用、严格 Schema、深复制和深冻结校验。
- 内置事件注册表覆盖对局就绪、公告、公开消息、投票结果、席位信息、真相变化和裁量请求。隐藏的已知事件返回 `null`；未知类型抛出房主侧结构化错误；输出不保留权威事件 ID、序号、因果命令、执行者和记录时间。
- 新增固定三席位虚构夹具、42 条单元测试和 4 条场景测试。夹具包含真实/认知身份不一致、未知醉酒/中毒、唯一敏感标记、跨席位规则信息、公开流程、裁量任务和审计；场景测试递归扫描禁止键与值，并用固定种子执行 24 轮变形。
- 测试先行红灯已确认：实现前两组新增测试均因 `@/domain/views` 不存在而失败；实现后新增 46 条测试全部通过。
- 新模块及新增测试独立 ESLint 为 0 错误、0 警告。`src/domain/views/` 覆盖率门禁为语句 80%、分支 70%、函数 80%、行 80%；实际行覆盖 220/237（92.82%）、分支 94/111（84.68%）、函数 66/67（98.50%），门禁通过。
- `npm run test:coverage` 通过：17 个 Jest 套件、145 条测试全部通过；全仓语句 58.60%、分支 44.94%、函数 56.47%、行 59.54%。
- `npm run test:ci` 通过：120 条单元、3 条组件、16 条场景、6 条集成测试，Lint 0 错误且 415 条遗留警告预算持平，生产构建成功，Chromium 端到端 3/3 通过。
- 产品、架构、路线图和文档索引已同步；M1-R2 领域协议与遗留 UI/WebSocket 均未修改，没有连接线上服务、调用真实 LLM、Push、创建 PR 或部署。

## 风险与后续接入边界

- M1-R3 使用固定只读源契约可避免提前污染 M1-R2 持久化格式，但后续真实权威状态接入必须建立受控适配器和同一泄漏矩阵，不能让组件自行拼装。
- 完全隐藏事件不返回占位可以避免侧信道，但后续在线协议需要设计房主侧源游标和客户端视图游标，不能直接公开权威事件序号。
