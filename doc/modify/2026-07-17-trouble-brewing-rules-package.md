## 元信息

- 状态：已实现，完整门禁通过
- 创建日期：2026-07-17
- 关联里程碑：[M1 规则内核、事件模型与权限视图](../milestone/roadmap.md)
- 前置需求：M1-R1 至 M1-R6
- 负责人：Codex

- 领域协议目标版本：`0.5.0`
- 规则集范围：`botc-ai.m1-ruleset-scope@0.2.0`

## 背景与问题

M1-R1 至 M1-R6 已冻结中文版规则来源、可重放领域协议、参与者权限、阶段与基础规则、提名投票以及通用角色能力执行框架，但尚没有一个能把具体角色身份、夜间顺序、被动能力、信息能力、特殊死亡与特殊胜利组合成完整对局的剧本规则包。本需求交付《暗流涌动》22 个角色的确定性规则包，使后续 UI 与 Agent 可以只通过统一命令、领域事件和座位视图参与对局。

M1-R1 固定的中文正式名为“镇长、陌客、红唇女郎”。需求语境中的“市长、隐士、猩红女郎”仅作为搜索和展示兼容别名，不改变稳定角色 ID、正式名或规则语义。

## 目标与成功标准

- 22 个角色均有稳定 ID、固定中文官方来源、能力定义、夜间/白天触发点、状态读写、权限和失效语义。
- 5 至 15 名非旅行者的标准角色数量、男爵调整、酒鬼伪装身份、占卜师干扰项、邪恶阵营互认与恶魔伪装角色均可由固定种子重放。
- 所有可以机械验证的规则由代码决定；说书人只在官方规则明确允许的候选集合内裁量，并通过可重放裁量任务提交选择。
- 角色能力不直接修改魔典对象，而是经 M1-R6 的触发、效果计划、裁量和语义事件链执行。
- 22 个角色各自覆盖正常、醉酒/中毒、死亡/失去能力、角色变化和至少一个适用相克场景；全部门禁通过且无真实 LLM、外部会话或生产数据依赖。

## 用户与使用场景

- 房主浏览器中的人类说书人或 AI 说书人创建《暗流涌动》对局，提交受约束的角色分配与必要裁量。
- 人类和 AI 玩家只读取本座位公开与私密视图，提交同一套夜间选择、提名、投票和公开能力动作。
- 旁观者和普通玩家不得读取真相角色、酒鬼伪装、占卜师干扰项、邪恶互认信息、恶魔伪装角色、间谍魔典或裁量候选全集。

## 已确认需求

1. 本需求一次性交付 M1-R7，不启动 M1-R8 或任何 Agent、UI 编排与真实供应商接入。
2. 规则来源只采用 M1-R1 固定范围与本需求新增的 22 个中文官方角色页固定修订；同步时同时校验 MediaWiki Wikitext SHA-256。
3. 标准开局人数为 5 至 15 名非旅行者；角色分配可由房主显式提交，也可由固定种子生成，但两条路径必须通过相同不变量。
4. 夜间顺序固定采用 `zh-wiki-tb@2716` 所列《暗流涌动》顺序，不随外部站点后续修订漂移。
5. 中毒和醉酒统一复用 M1-R6 的能力失效与错误信息语义；信息能力仍建立可追踪裁量任务，非信息能力不产生规则效果。
6. 陌客和间谍的“可能被当作”不等于获得能力或改变真实阵营；每次适用检测由说书人在受约束候选中选择登记结果。
7. 管家违规投票按官方规则仍计票：系统不回滚或拒绝投票，在投票结束时确定性记录违规审计事件。
8. 所有自动随机选择只使用对局固定种子与领域状态派生随机流；裁量任务不调用真实 LLM。

- 猎手在白天通过一次公开能力动作触发；贞洁者由首次被提名触发；被动保护、登记、特殊胜利和角色变化由对应领域事件触发。

## 非范围

- 不实现 M1-R8 及后续规则包、Agent Skill、提示词策略、自动说书人决策质量或真实 LLM Provider。
- 不实现房间 UI、魔典视觉组件、WebSocket 会话同步、存档迁移界面或线上服务。
- 不纳入旅行者、实验性角色、传奇角色、其他剧本和自定义剧本。
- 不把官方“说书人可选择”的裁量改造成隐式随机，也不自动判断玩家是否故意违反管家投票限制。
- 不同步固定修订之后的 Wiki 内容，不恢复对 townsquare 或其他外部仓库的隐式跟踪。

说书人不得自由提交任意文本或任意状态补丁。裁量任务必须包含来源、候选、私密范围、固定输入摘要和确定性验证器；提交无效候选不消耗能力，允许重试或取消尚未提交的交互。

## 交互与失败恢复

1. 创建对局时加载规则包并验证来源完整性、协议版本和 22 个稳定角色 ID；加载失败不得产生部分对局。
2. 开局先提交角色列表、座位真相和所需开局裁量，再原子产生开局事件；任一不变量失败时整批拒绝。
3. 夜间按固定优先级一次只打开当前触发；需要玩家选择时进入可取消交互，需要说书人选择时进入裁量任务。取消不消耗能力，提交成功后重复请求以命令 ID 幂等返回。
4. 玩家超时不由规则包自行代选；上层可显式提交由房主策略生成的合法动作。规则包只验证动作，不依赖计时器或在线后端。
5. 裁量任务提交非法候选、过期任务或越权身份时返回稳定错误码，原任务保持待处理；真相状态不被部分更新。
6. 断线恢复重放同一事件日志，并恢复待处理触发、玩家交互、裁量任务、条件生命周期和夜间游标；不得重新随机。
7. 无法完成的夜间动作只能由显式房主命令按协议跳过，并记录来源和原因；系统不得静默吞掉。

## 状态、事件与权限

### 状态模型

在 `0.4.0` 基础上新增或具体化：

- `seats[*].actualRoleId/perceivedRoleId/alignment/roleInstanceId`：分别保存说书人真相、座位感知身份、真实阵营和角色实例；酒鬼的真实/感知身份不同。
- `troubleBrewing.packageId/version/setup`：固定包身份、占卜师干扰项、恶魔伪装角色和 7 人以上邪恶阵营席位集合。
- `troubleBrewing.information/markers/deathHistory/registrationHistory/publicActions/butlerViolations`：以稳定记录 ID 保存包内私密信息、角色标记和来源化审计。
- `abilityInstances/abilityConditions/abilityTriggers/ongoingAbilityEffects/adjudicationTasks`：继续复用 M1-R6 保存次数、醉酒/中毒、夜间游标、保护与说书人裁量；规则包不复制第二套通用状态。
- `executionToday`：沿用基础内核区分被处决和因处决实际死亡；死亡保护、转移和继任在同一命令的候选事件链中计算，不暴露可被调用方任意改写的待处理死亡对象。

### 命令与事件

- `game.start` 的包内开局钩子在提交前重算角色数量、席位、能力实例和 `troubleBrewing` 状态；开始事件的反应器再建立酒鬼条件并投递邪恶方私密信息。
- 夜间和领域触发继续使用 M1-R6 的 `ability.trigger.resolve/cancel` 与裁量命令；猎手额外通过包专用 `tb.slayer.use` 产生一次公开领域触发。
- `player.kill`、`execution.resolve` 和小恶魔/猎手/贞洁者处理器使用同一死亡求值与语义事件构造器，顺序处理保护、免疫、转移、实际死亡、继任和胜负。
- 处决完成、圣徒失败、镇长三人生还胜利、守鸦人夜死、角色变化和管家投票审计均由明确事件反应器派生，不由调用方提交结果字段。
- 包内 16 种语义事件都通过角色包白名单、严格负载 Schema、纯归约器、来源引用和重放不变量校验。

M1-R6 的通用最小扩展限于包内固定来源、四个角色无关规则钩子、状态相关输入/裁量验证和失效尝试计划。通用层不包含《暗流涌动》角色 ID；具体命令、事件、反应器和不变量均留在本包。

### 权限

- 说书人真相视图：全部真实角色、感知角色、条件、登记选择、裁量候选、干扰项、邪恶信息和魔典。
- 座位私密视图：自己的感知身份、按规则收到的信息、自己的待处理交互；邪恶互认、伪装角色和间谍魔典仅进入对应座位。
- 普通公开视图：座次、存活、公开提名投票、公开猎手动作、公开死亡与胜负；不暴露能力是否有效、死亡被保护/转移的隐藏原因或真实角色。
- Agent 观察仍由座位视图派生，不接收真相事件后再做字段过滤。

## Agent、Skill 与 LLM 约束

M1-R7 不新增 Agent、Skill 或 Provider。所有裁量测试使用确定性夹具，所有玩家动作由测试显式提交。未来 Agent 只能读取其身份对应视图并调用已授权命令；不得把真相魔典、其他玩家私聊或裁量候选全集放入玩家上下文。超时、限流、成本统计和供应商差异属于 M2 Provider/Agent 需求，M1-R7 不调用真实模型且没有付费依赖。

## 兼容、迁移与回滚

- 领域协议升级到 `0.5.0`；空框架场景继续使用可选的新字段，但 `0.4.0` 及更早事件流不会由 `0.5.0` 引擎静默归约或补齐。
- 不迁移现有浏览器对局；缺少固定规则包身份或协议版本不一致的旧快照明确拒绝，不能伪装成完整《暗流涌动》对局。
- 规则包与通用框架通过版本和完整性摘要绑定；不兼容版本加载时明确失败。
- 回滚本提交即可移除规则包和通用扩展；无数据库、线上会话、外部服务或生产数据副作用。

## 验收标准

- 22 个角色来源全部固定到明确修订并通过 Wikitext SHA-256 校验，来源注册表完整性可测试。
- 5 至 15 人标准数量、男爵调整、酒鬼伪装、占卜师干扰项、邪恶互认与恶魔伪装角色均通过有效和无效输入测试。
- 两套夜间顺序与角色触发匹配固定剧本页；同一固定种子、命令流和裁量选择产生字节级稳定快照。
- 22 个角色均存在正常、醉酒/中毒、死亡/失去能力、角色变化和适用相克回归用例，且覆盖其主要能力效果。
- 陌客/间谍登记、镇长转移、小恶魔继任和错误信息只能提交合法候选；越权或非法候选不改变状态。
- 圣徒、镇长、红唇女郎、小恶魔、贞洁者、士兵、僧侣等会影响死亡、处决或胜负顺序的场景没有提前结算。
- 各参与者视图中无真相角色、私密信息、裁量候选或魔典越权。
- `npm run test:ci`、相关覆盖率门禁和变更文件 ESLint 全部通过，遗留 Lint 警告不增加。

## 测试方案

### 单元测试

- 来源注册表、角色包 schema、角色数量、男爵调整、开局私密状态、固定夜间顺序与规则包完整性。
- 每个角色使用参数化测试覆盖：正常有效、醉酒/中毒、死亡或能力失活、角色变化后的新旧实例、一个适用相克；一次性角色另测重复提交。
- 死亡管线覆盖恶魔伤害、保护、免疫、镇长转移、处决实际死亡、圣徒失败、红唇女郎继任、小恶魔自杀及无继任者。
- 信息能力覆盖正常候选、陌客/间谍登记、错误信息、非法裁量和私密投影。

### 场景与集成测试

- 固定 5 人、7 人、10 人、15 人开局与男爵/酒鬼组合。
- 集成场景分别覆盖投毒/保护/恶魔攻击、守鸦人夜死与信息、贞洁者处决、圣徒失败、红唇女郎继任、镇长三人生还胜利和猎手公开击杀；固定事件日志验证开局队列与猎手胜利可原样恢复。
- 管家先于主人和后于主人投票两种座次均在投票关闭时得到相同合规判断，违规票仍计数。
- 角色变化场景验证红唇女郎/其他爪牙变成小恶魔后旧能力失活、新恶魔当夜不重复行动。

### 端到端与人工检查

UI 尚未消费该规则包，新增浏览器 UI 端到端不适用；保留现有 Chromium 回归。人工检查只核对文档、协议和产品描述的一致性，不连接真实 Wiki、线上会话或付费 LLM。

## 实现计划

1. 先写固定来源、规则包结构、开局不变量与 22 角色矩阵的失败测试。
2. 以回归测试为驱动补齐 M1-R6 的最小包内来源、手动触发和结算策略扩展。
3. 实现《暗流涌动》开局、夜间队列、角色能力、死亡/处决/胜利管线和权限投影。
4. 补齐每角色五类测试、关键事件日志回放与固定种子裁量测试。
5. 同步产品、架构、里程碑、文档索引和领域协议，执行完整质量门禁并本地提交。

## 风险与待确认项

- 无影响实现的待确认项。22 个角色页、共同规则页、人数表和夜间顺序均已固定并完成哈希校验。
- M1-R6 当前缺少包内固定来源、公开手动能力触发以及可插入保护/继任/特殊胜利的结算前置点；本需求仅做角色无关的最小扩展，并由既有规则回归与《暗流涌动》场景共同约束。
- 官方规则允许说书人对信息、登记、镇长转移和部分继任作选择；实现必须保留显式裁量记录，不能以“更智能”为由把选择固化成隐藏业务分支。
