- 状态：本地完成

## 背景与问题

M1-R2 至 M1-R5 已建立可重放领域协议、参与者权限视图、基础昼夜/生死/胜负以及提名投票规则，但权威内核仍只认识角色类型，不认识某项能力来自哪个角色实例、何时应进入首夜或其他夜队列、持续和延迟效果何时仍有效，也没有受约束的说书人裁量任务。若具体角色规则直接各自修改状态，醉酒、中毒、死亡、角色变化、限次使用、断线重试和日志恢复会产生互相冲突的隐式语义。

M1-R6 建立不包含任何具体角色行为的执行框架：对局精确绑定一个版本化角色规则包；规则包用不可变清单声明能力、来源、触发、权限、限次和效果边界，用受信纯处理器返回严格结构化效果计划；内核把能力实例、触发队列、持续/延迟效果和裁量任务写成可重放领域事件。M1-R7 至 M1-R11 只需逐包注册具体角色定义和语义事件，不能绕过该框架获得任意状态写权限。

## 目标、用户价值与成功指标

- 同一规则集对局精确绑定一个角色规则包 ID、语义版本和完整性哈希；包缺失、版本漂移、来源漂移或恢复时传入不同包均失败关闭。
- 每个能力实例保存稳定实例 ID、定义 ID、拥有席位、来源角色/角色实例和用量；角色变化通过原子替换能力实例，旧实例触发、效果和任务不会泄漏到新角色。
- 首夜、其他夜、进场和白天领域事件触发由内核按包内优先级、席位顺序与稳定 ID 自动排队；调用方不能传入任意夜间顺序、插队或跳过未完成前项。
- 能力处理器只读取冻结状态、冻结触发与已校验输入，并返回严格效果计划；只允许产生定义白名单内的已注册语义事件、持续/延迟效果或裁量任务，不接受 JSON Patch、任意状态字段或可执行代码数据。
- 醉酒、中毒、死亡/失去能力、复活和角色变化对能力有效性、限次消费、持续/延迟效果及信息裁量采用统一生命周期；具体角色仅声明官方例外。
- 说书人裁量任务保存来源、合法候选/结果 Schema、可见性、状态和因果触发；只有 Host/System 可以解决或取消，裸 Agent、Seat、Observer 不能读取完整任务或直接提交结果。
- 相同命令重试只产生一次用量、效果或任务；完整日志恢复得到相同队列、任务和效果，损坏或不兼容数据不可恢复为可写状态。
- 新模块通过针对性单元/场景测试、模块覆盖率、Lint、生产构建和 Chromium 端到端门禁，不依赖真实 LLM、线上会话、动态 Wiki 或生产数据。

## 用户与使用场景

- 房主在创建对局时由本地构建选择一个已安装且通过校验的规则包。普通用户不能在对局中热替换规则包。
- 具体角色规则包在开局命令中提供经清单校验的能力实例；框架在 `game.started` 后自动建立首夜队列。之后进入普通夜晚时自动建立其他夜队列。
- 白天或即时能力监听明确的领域事件类型。原始事件成功归约后，框架按固定顺序追加 `ability.trigger.queued`；一个命令及其连锁事件作为同一原子批次提交。
- 当前触发需要玩家选择时，拥有席位以 Seat 主体提交定义专属输入；房主可在断线或超时时代理。无需玩家选择时由 Host/System 结算。
- 结果唯一可确定时，处理器返回语义事件和效果记录；官方规则要求说书人选择真假信息、模糊注册或开放候选时，处理器只创建合法范围内的裁量任务。说书人解决任务后，内核再次校验结果并生成语义事件。
- 醉酒或中毒玩家仍按正常流程行动并消耗限次尝试；确定性效果不生效。信息能力只能进入该定义声明的“醉酒/中毒信息”裁量路径，不允许调用方直接填写任意私密文本。
- 角色变化时由具体规则包同时提交自身的角色语义事件和框架的能力实例替换；框架终止旧来源的待触发、持续/延迟效果与未决任务，并为新实例按“进场/当前阶段尽快”声明重新排队。

## 规则来源与已确认结论

本需求以 `knowledge/rulesets/m1-ruleset-scope.json@0.2.0` 及完整性 `sha256:aa2daef3eb6d5c29f944fa431837823eb1faea472aed71146f1a4d8a71e5dd2d` 为唯一规则范围身份。开发现场读取以下清单内固定中文官方修订，临时正文仅位于被 Git 忽略的 `.work/m1-r6-role-ability-framework/`：

- `zh-wiki-glossary@6017`、`zh-wiki-important-details@4183`、`zh-wiki-ability-categories@3997`：能力立即生效；说书人只能告知能力允许得知的信息；角色状态、阵营、生死、醉酒与中毒是彼此独立的事实。
- `zh-wiki-ability-drunk@5720`、`zh-wiki-ability-poisoned@6294`：醉酒/中毒者表现为能力仍在运作；确定性效果不生效，信息可由说书人在合法语境中给出正确或错误结果，限次尝试仍消费；恢复清醒/健康后能力与仍满足期限的持续效果恢复，已消费次数不恢复。
- `zh-wiki-ability-character-change@5755`、`zh-wiki-ability-entry-ability@5962`：角色变化产生新的角色与能力实例，旧能力及其持续效果结束；新角色的进场/首夜能力在可行时尽快触发，按角色计的限次能力重置；仅初始设置生效的括号内容不在中途重做。
- `zh-wiki-ability-post-death-ability-retention@6318`、`zh-wiki-ability-death-triggered-ability@6308`、`zh-wiki-ability-resurrection@5754`：普通能力在死亡时失效，明确的死后保留或死亡触发能力除外；死亡瞬间触发与“得知自己死亡时”是不同触发；复活只恢复当前角色仍拥有的能力，不复原已经结束的旧角色实例。
- `zh-wiki-ability-limited-use-ability@6297`：限次按能力实例记录，尝试而非最终效果决定是否消费；角色变化得到的新实例按官方角色规则重置。
- `zh-wiki-ability-continuous-detection@6329`、`zh-wiki-ability-ability-effect-interference@5915`、`zh-wiki-ability-selection-retargeting@5509`：持续检测必须在相关领域事实变化后重新评估；能力冲突和更换目标应由明确优先级与来源事件表达，不能依赖组件调用先后。
- `zh-wiki-ability-information-gain@6386`、`zh-wiki-ability-public-triggered-ability@6385`：信息只投递给规则允许的接收者；公开触发与私密信息是不同事件和视图语义。
- `zh-wiki-ability-protection@4763`、`zh-wiki-ability-death-immunity@5964`：被保护或免死而没有实际死亡时，不产生死亡事件，也不触发死亡能力。

来源冲突优先级固定为显式勘误/相克规则、角色 Almanac、角色能力文字、通用规则；中文官方来源为规范结论，英文只可填补中文缺口且不能覆盖中文。每个具体能力定义必须引用 M1-R1 已固定的 `sourceId`；来源修订和正文哈希由规则集身份追踪，运行时不访问网页。

由这些来源和既有架构边界可唯一确定：

- 能力有效性是归约状态的派生事实，不由调用方传入 `isEffective`。普通能力要求实例有效、拥有者存活且未受醉酒/中毒/失去能力影响；包清单可为官方明确的死后能力声明例外，但醉酒/中毒仍使其失效。
- 持续效果记录不因短暂醉酒/中毒或普通死亡删除，而是按来源实例和期限派生为暂停；恢复清醒、健康或复活时，如果原角色实例仍存在且期限未结束则恢复。角色变化会终止旧实例效果，不可恢复。
- 延迟效果到达声明的领域触发点才排队；来源实例已被替换、效果已取消或期限已结束时确定性取消，不能在恢复后补执行已经错过且规则未声明可补发的触发。
- 夜间顺序由能力定义的 `priority`、拥有席位当前顺序、能力定义 ID、实例 ID 稳定排序。官方夜顺序表是默认指导，具体能力文字或相克规则可在具体包中给出更高优先级声明。
- 同一来源事件、实例和触发定义只能生成一个稳定触发 ID；命令重试或连锁反应不能重复排队。连锁扩展设置硬上限并在超限时整批失败。
- 非法玩家选择形成领域拒绝，玩家重新选择；框架不自动纠正为合法目标。说书人裁量也只能从候选集合或结果 Schema 中选择，不能输出任意状态变更。

## 已确认范围与边界

### 范围

- 将领域协议从 `0.3.0` 演进为 `0.4.0`，在对局、每个事件与事件流中加入精确角色规则包身份并严格校验。
- 新增 `knowledge/rulesets/role-ability-package.schema.json`、不含具体角色的 M1-R6 空框架包清单，以及浏览器兼容的清单完整性验证与编译 API。
- 规则包清单声明角色能力定义、固定来源、触发种类/优先级、动作主体、限次、死亡保留、醉酒/中毒策略、允许语义事件和结构化输入/裁量结果 Schema；运行处理器与清单分离，不进入日志或状态。
- 权威状态新增能力实例、能力状态条件、待处理触发、持续效果、延迟效果和裁量任务；所有记录都保存稳定 ID、来源能力实例、规则来源、状态与创建修订。
- 新增通用能力实例替换、状态条件变更、触发结算、效果取消和裁量解决/取消命令及事件；命令负载严格，无任意 Patch 或状态覆盖字段。
- 命令总线新增确定性事件反应器和规则包不变量扩展点：按固定优先级展开候选事件，限制连锁数量，整批归约后与重放命令边界执行全部不变量。
- 开局能力实例随 `game.start` 一次提交并由当前规则包校验；首夜、其他夜、进场、白天及延迟触发由反应器自动排队。
- 提供能力/效果有效性选择器和包内虚构能力测试夹具，覆盖确定性效果、信息裁量、醉酒/中毒、死亡/复活、角色变化、限次、取消、幂等与重放。
- 同步重写产品、架构、领域协议 README、里程碑状态与需求索引，说明 M1-R7 至 M1-R12 的接入边界。

### 非范围

- 不实现暗流涌动、黯月初升、梦殒春宵、旅行者、传奇角色或奇遇角色中的任何具体能力、相克、设置修正、特殊胜负或剧本分配。
- 不给 M1-R5 提名/投票增加具体角色权重、额外提名、死亡保护、处决替代或特殊门槛；具体语义事件由 M1-R7 至 M1-R11 分包实现。
- 不完成真实角色、阵营、认知角色、公开角色或角色分配状态；能力实例只保存执行所需的来源引用，完整魔典真相模型由具体规则包与 M1-R12 适配。
- 不把裁量任务、能力真相或私密信息投影到 Public/Observer。M1-R3 视图协议保持 `0.2.0`；M1-R12 在房主可信边界内建立真实状态适配与中文 UI。
- 不实现 Agent Prompt、Skill、Provider、自动说书人决策或玩家策略；M1-R6 只提供可被后续受控工具调用的命令边界。
- 不实现 IndexedDB、检查点压缩、跨版本事件迁移、日志签名或在线协议；旧 `0.1.0` 至 `0.3.0` 日志继续失败关闭并可由外围只读导出诊断。
- 不访问线上会话、真实 LLM、生产数据或动态 Wiki；不 Push、不创建 PR、不部署。

## 版本化规则包与兼容绑定

角色规则包清单必须是严格 JSON，至少包含：

- `packageId`、`version`、`frameworkVersion`、`canonicalLanguage` 与 `integrity`；完整性覆盖移除 `integrity` 后的规范化 JSON。
- `ruleset`：完整复制并精确绑定 M1-R1 的规则集 ID、版本、来源清单版本与完整性，不接受只比较 ID 或宽松版本范围。
- `abilities`：按稳定 ID 排序的能力定义；每项保存 `roleId`、`sourceRefs`、触发定义、动作主体、使用次数、死亡保留、醉酒/中毒策略、输入 Schema、允许语义事件和裁量结果 Schema。
- `eventTypes`：该包可产生的具体语义事件清单；运行时还必须注册同名且严格的事件定义。清单之外的事件即使引擎已注册也不能由能力处理器产生。

仓库自带的 `botc-ai.m1-role-ability-framework@0.1.0` 是能力列表为空的框架包，只用于保持 M1-R2 至 M1-R5 场景可运行，不宣称任何角色已经实现。具体规则包使用独立 ID 和不可变版本；内容变化必须升级版本并重新计算哈希，不能覆盖已被日志引用的版本。

创建协议实例时只装载一个已编译规则包。`game.create` 命令必须提交该包身份；事件信封、状态与事件流重复保存同一身份。恢复时调用方必须再次提供完全相同且通过完整性校验的包；缺包、错包、处理器缺失、事件定义不匹配或规则集不匹配均在重放前失败。运行函数本身不序列化，包完整性和构建制品版本共同承担恢复绑定；未来签名和受信发布属于安全里程碑。

## 能力实例、触发与确定性效果模型

### 能力实例与来源

能力实例字段固定为 `instanceId`、`definitionId`、`ownerSeatId`、`sourceRoleId`、`sourceRoleInstanceId`、`status`、`usesConsumed` 和 `createdAtRevision`。开局命令可以提交空数组；非空实例必须全部引用当前包定义、现有唯一席位、匹配的来源角色，并且 ID 全局唯一。

角色变化不由框架猜测新角色或阵营。具体规则包提交语义角色变化事件，同时使用 `ability.instances.replace` 指定席位、旧角色实例、新实例集合和原因。归约器原子地把旧实例标记为 `replaced`，取消其待触发、未决裁量和延迟效果，终止其持续效果，再激活新实例。若具体包未同时提供完整角色语义事件，框架只完成能力生命周期，不伪造角色真相。

### 触发时机与队列

触发定义使用封闭种类：`first-night`、`other-night`、`entry`、`domain-event` 和 `delayed`。`domain-event` 必须列出一个或多个已注册领域事件类型；不能监听通配符。每个定义保存整数 `priority`，数值越小越早。

反应器在每个原始或连锁事件成功归约后读取冻结的新状态，按以下顺序生成候选事件：反应器优先级、能力触发优先级、席位顺序、定义 ID、实例 ID。`game.started` 产生首夜队列；进入普通 `night` 产生其他夜队列；实例替换产生进场队列；明确领域事件产生白天/即时队列；到期延迟效果产生延迟队列。触发保存来源事件 ID、阶段与日夜号，使日志可解释且重放不重新运行反应器。

同一时间只允许结算队首未取消触发。存在由该触发创建的未决裁量任务时，后续触发阻塞；任务解决或取消后原触发完成，队列才继续。阶段推进时若当前阶段仍有必须处理的触发或任务则拒绝；具体包可把官方明确“可跳过”的触发声明为可取消，但取消必须形成事件和原因。

### 处理器与效果计划

每个能力定义对应一个受信处理器。处理器输入为冻结的权威状态、能力实例、触发、当前有效性、已校验动作输入和确定性上下文；不得接收网络、时钟、随机数、DOM、LLM 或可变内部状态。处理器输出只允许：

- `events`：已注册、Schema 合法且在该能力白名单中的具体语义事件候选；归约器负责真实状态变化。
- `ongoingEffects`：稳定效果 ID、来源实例、类型、目标引用、开始/结束触发和规则来源；后续规则只通过选择器读取其当前是否有效。
- `delayedEffects`：稳定效果 ID、来源实例、到期领域触发、载荷类型和规则来源；到期后转为单一触发或确定性取消。
- `adjudicationTask`：任务 ID、种类、中文摘要、规则来源、候选席位/枚举、结果 Schema 与解决处理器 ID；一次结算最多创建一个。
- `consumeUse`：是否消费一次尝试；框架验证不超过清单上限。限次能力在醉酒/中毒时仍消费，普通无次数能力固定为 `false`。

输出对象拒绝额外字段，所有嵌套数据必须是可克隆 JSON；候选语义事件在进入引擎后再次执行事件 Schema、规则包白名单、身份和状态不变量校验。处理器抛错、返回非法计划、产生未知事件、重复效果 ID、超过用量或连锁上限时整批失败，不提交半个结果。

## 醉酒、中毒、死亡、恢复与效果生命周期

`ability.condition.set` 只接受 `drunk`、`poisoned`、`ability-disabled` 三种条件、稳定条件 ID、拥有席位、来源能力实例或受信系统来源及启停原因。该命令由 Host/System 或具体包的语义事件调用，不向 Seat 暴露通用“改变状态”工具。

能力有效性按结算时状态派生：

- 实例必须为 `active`，来源角色实例没有被替换；
- 拥有者存活，或定义明确 `retainsAfterDeath=true`；
- 没有活动的醉酒、中毒或失去能力条件；
- 使用次数未超过上限，触发仍在期限内。

无效的确定性能力不调用具体效果处理器，只记录已尝试/被抑制并按规则消费次数。信息能力只有定义声明 `intoxicationPolicy=storyteller-information` 时，才调用专用的醉酒/中毒裁量构造器；该构造器只能返回任务，不能直接产生语义状态事件。死亡触发在真实 `player.died` 后排队；保护或免死没有死亡事件，因此不会排队。

持续效果保留原始记录并通过 `isAbilityEffectActive` 派生是否生效：醉酒、中毒、普通死亡或失去能力会暂停，条件解除或复活后在原实例仍有效且期限未过时恢复；角色实例替换、明确取消或到达终止触发会永久结束。官方明确独立于来源角色存续的效果必须由具体包声明例外并提供来源测试。

延迟效果在暂停期间不执行。若到期点发生时来源无效，默认记录 `source-ineffective` 取消；只有具体定义显式声明可等待恢复才保留。限次消费不因条件解除、复活、重试或恢复日志而回滚。

## 结构化说书人裁量任务

任务生命周期为 `pending -> resolved|cancelled`，终态不可再修改。任务至少保存 `taskId`、`triggerId`、`abilityInstanceId`、`kind`、`summary`、`ruleSourceIds`、候选席位/枚举、结果 Schema、`visibility=storyteller-only`、创建修订和状态。禁止保存 Prompt、模型回复、API Key、私聊、自由文本魔典或调用方自定受众。

`ability.adjudication.resolve` 仅 Host/System 可提交，结果必须同时通过任务内 Schema、当前包处理器和当前状态候选复核；过期候选形成领域拒绝，调用方刷新后显式取消或重新创建，不能静默改选。解决处理器只返回该能力白名单内的语义事件与效果计划。`ability.adjudication.cancel` 仅允许来源实例被替换、触发失效、阶段被规则允许跳过或房主显式撤销尚未公开的错误操作，并保存封闭原因。

完整任务只属于 Storyteller 权限。Seat 只在规则要求其输入时看到自身合法动作，在任务解决后只接收规则允许的私密信息；Public/Observer 不看到任务或隐藏候选。M1-R6 不修改视图协议，M1-R12 的真实适配器必须按上述正向字段构造，不能把权威任务对象先广播再过滤。

## 交互、失败恢复、取消与幂等

- 未安装/不匹配规则包、非法能力实例、未知触发、非队首触发、错误主体、非法输入、使用次数耗尽、重复 ID、越界效果、任务候选过期和阶段仍有阻塞任务都返回中文领域拒绝；不产生事件。
- 相同命令 ID 与相同内容返回首次回执；同 ID 不同内容报幂等冲突。触发 ID由来源事件、实例和触发定义规范化派生，防止事件反应器在重试中重复排队。
- 处理器、反应器、Schema、归约器或不变量失败属于本地规则包/程序错误，整批候选事件不提交。UI 应进入只读诊断而不是猜测继续；外层可导出事件流、包身份和错误码。
- 玩家输入超时可由 Host/System 按具体角色规则代理合法选择或显式取消可跳过触发。框架不提供“任选默认目标”；说书人裁量超时同样保持 pending，Agent 失败不会绕过任务。
- 角色变化、效果取消与任务取消都有专用事件，不删除历史。日志重放只归约已记录事件，不再次执行处理器或反应器；恢复后继续的新命令使用再次装载并验证的同一规则包。
- 单命令连锁事件上限为 256；能力实例上限 256，活动触发、效果和任务分别设置 Schema 上限。超限失败关闭，后续持久化里程碑再引入安全快照和历史压缩。

## 状态、事件与权限

协议 `0.4.0` 在 `0.3.0` 上增加：

- `rulePackage`：不可变规则包身份，同时出现在状态、事件信封和事件流。
- `abilityInstances`：活动或已替换的能力实例及用量。
- `abilityConditions`：影响能力有效性的来源化条件。
- `abilityTriggers`：按确定性顺序保存 pending/resolved/cancelled 触发。
- `ongoingAbilityEffects`、`delayedAbilityEffects`：来源化、可暂停/终止的效果记录。
- `adjudicationTasks`：仅说书人可见的 pending/resolved/cancelled 任务。

新增命令与事件采用 `ability.*` 命名；具体包的角色语义事件使用包拥有的稳定前缀。Host/System 可以创建对局、提供开局实例、代理玩家输入、解决裁量、取消允许取消的效果；Seat 只能为自己当前队首且定义为 `seat` 的触发提交动作。Observer、裸 `agent` 无写权限；未来 AI 玩家由可信网关映射到 Seat，AI 说书人映射为受控 Host/System 意图。

每个成功命令边界与恢复边界验证：规则集/包身份不变；实例、触发、条件、效果和任务 ID 唯一；所有引用存在；队列顺序稳定；用量不超限；终态不可倒退；待裁量任务与触发一一绑定；旧角色实例没有活动触发或效果；准备/结束阶段不存在非法活动任务。

## Agent、Skill 与 LLM 约束

M1-R6 不新增 Prompt、Skill、Provider 或真实 Agent。框架命令是未来 Skills 的受限工具底座，不是可直接暴露给模型的通用状态编辑器。AI 玩家只能从 SeatView 获得自身合法触发和输入 Schema；AI 说书人只能从 StorytellerView 获得结构化任务。即使模型输出合法 JSON，也必须经过同一主体权限、Schema、候选、修订、规则包和状态不变量校验。

供应商差异、流式输出、超时、限流、成本与降级属于后续 Agent Runtime。M1-R6 测试只用同步确定性假处理器；处理器没有网络或模型依赖。Agent 取消不能取消已提交的领域事件，只能停止尚未提交的推理并由受信控制器显式取消仍允许取消的任务。

## 兼容、迁移与回滚

- 协议、Schema 和事件流版本升级为 `0.4.0`；旧 `0.1.0` 至 `0.3.0` 事件流不静默升级，恢复时报明确不支持。跨版本迁移需在持久化里程碑中以独立、可审计转换实现。
- M1-R3 参与者视图协议保持 `0.2.0`。现有固定夹具和视图服务不读取新增权威字段；M1-R12 适配时另行升级视图源。
- 空框架包作为默认包，使现有基础规则场景继续运行且新增能力集合为空。它不能与未来具体角色包混用，也不能证明 M1-R7 至 M1-R11 已完成。
- 回滚本地提交即可回到 `0.3.0`；已产生的 `0.4.0` 日志在旧代码中只读不可写。无线上数据迁移、配置变更或部署副作用。

## 验收标准

- 空框架包清单通过严格 Schema、语义检查和规范化完整性哈希；任一字段篡改、规则集身份漂移、重复定义、未知来源或缺失处理器都无法编译。
- `game.create`、事件、状态和事件流精确保存规则包身份；用错包恢复在归约前失败，正确包恢复与原状态、队列、效果、任务和回执完全一致。
- 虚构测试能力可在首夜、其他夜、进场和白天事件后按固定顺序自动排队；非队首不能结算，阶段有阻塞项时不能推进，连锁超限整批失败。
- 确定性虚构能力只产生白名单内严格事件；非法效果计划、未知事件、任意额外字段和状态补丁失败且不污染日志。
- 醉酒/中毒的确定性能力不生效但消费限次；信息能力只产生结构化说书人任务；恢复清醒/健康不会返还用量。
- 普通死亡暂停普通能力与持续效果，明确死后保留能力仍可触发；复活只恢复仍属于同一来源实例的效果；没有死亡事件时不触发死亡能力。
- 角色变化原子替换实例并终止旧触发、效果和任务；新实例进场触发和限次从新实例开始，不复活旧实例。
- 裁量任务只能由 Host/System 以合法结果解决或封闭原因取消；Seat/Public/Observer 接口不泄露完整任务，解决重试不重复产生结果。
- 针对性测试、模块覆盖率、完整 `npm run test:coverage` 与 `npm run test:ci` 全部通过；差异仅包含 M1-R6 代码、测试和融合后的文档。

## 测试方案

- 清单单元测试：Schema、规范化哈希、规则集精确绑定、稳定排序、来源存在性、定义/处理器/事件白名单一致性及所有篡改失败场景。
- 引擎单元测试：事件反应器固定排序、冻结输入、候选校验、连锁上限、原子失败、扩展不变量及恢复时不重复运行反应器。
- 框架单元测试：开局实例、首夜/其他夜/进场/领域事件队列、Seat/Host 权限、限次、无效能力、持续/延迟效果、取消和任务生命周期。
- 来源矩阵测试：以虚构能力分别覆盖正常、醉酒、中毒、死亡/死后保留、复活、角色变化、限次和效果干扰；用例元数据引用上述固定中文 `sourceId`。
- 场景测试：完整“首夜结算—白天事件触发—醉酒信息裁量—角色变化—其他夜—导出恢复—幂等重试”日志，比较原/恢复状态和事件。
- 回归测试：M1-R2 至 M1-R5 全部协议、基础规则、提名投票和权限视图测试继续通过；空包不改变无角色能力场景的业务结果。
- 覆盖率：为 `src/domain/abilities/` 设置 statements/lines/functions `>=95%`、branches `>=90%` 的模块门禁；同时运行全仓 `npm run test:coverage`。
- 集成、Lint、构建与端到端：执行 `npm run lint-ci`、生产构建和完整 `npm run test:ci`。真实 Provider、线上中继、动态 Wiki、性能压测和生产数据不适用。

## 性能、迁移与回滚风险

- 事件反应器使单命令可能扩展多个事件。固定排序、精确事件监听和 256 事件硬上限避免通配扫描与无限循环；规则包应为事件类型建立索引，典型复杂度为“相关实例数排序”，不遍历 Wiki 正文。
- 历史能力实例、效果和任务会增长。M1-R6 保留完整可重放记录并设置活动项上限；长期归档、快照压缩与校验签名留给持久化里程碑。
- 运行处理器不能由 JSON 完整性直接覆盖。当前信任仓库构建制品，并用包身份、处理器集合一致性和固定测试约束；第三方规则包签名、沙箱和供应链验证属于后续安全需求。
- M1-R4 的即时常规胜负先于未来保护、特殊胜负或胜负阻止语义。M1-R6 只提供前置/连锁事件能力，不擅自改变具体规则；M1-R7 至 M1-R11 接入这些能力时必须为相关命令定义明确优先级和新回归场景。

## 后续节点边界

- M1-R7 至 M1-R11：分别提供真实角色包清单、处理器、角色语义事件、相克/勘误和每角色来源矩阵；不得修改框架以加入只对单一角色有意义的布尔开关。
- M1-R12：把权威能力状态、合法动作、已投递信息和裁量任务正向适配为中文魔典 UI 与 M1-R3 权限视图；不在客户端重算规则。
- M2：继续补齐固定规则正文、检索和引用，用于解释与裁量，不绕过规则包处理器改状态。
- M3/M4：通过 SeatView/StorytellerView 与受限 Skills 驱动相同命令；Agent Runtime 不获得规则内核内部对象。
