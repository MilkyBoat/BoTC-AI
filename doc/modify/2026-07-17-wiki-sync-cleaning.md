# Wiki 同步与清洗工具

## 元信息

- 状态：本地完成
- 创建日期：2026-07-17
- 关联里程碑：[M2-R2 Wiki 同步与清洗工具](../milestone/roadmap.md#m2官方规则知识与浏览器-agent-基座)
- 负责人：Codex

## 背景与问题

M1-R1 已冻结三个基础剧本、特殊角色和通用概念的范围，并记录 39 个中文官方 Wiki 固定修订及原始 Wikitext 哈希，但仓库尚无可重复运行的页面同步与正文清洗工具。相邻实验项目 `../blood_on_clocktower_ai` 的爬虫可以帮助识别页面入口、正文容器、内部链接和 Markdown 落盘需求，但其实现使用正则解析嵌套 HTML，未完整处理 HTTP 状态、重定向、超时、限流、修订校验、结构化表格、重复内容和失败报告，生成内容也会混入导航或丢失结构。

本需求在 BotC-AI 内重新设计同步流水线。工具必须把网络和 Wiki 内容视为不可信输入，使用 DOM 解析器提取正文，以固定修订清单约束同步范围，并产出可追溯、可测试的 Markdown、元数据和质量报告。相邻项目只作为思路参考，不复制其业务模块、正则解析器或知识目录实现。

## 目标与成功标准

- 开发者可以用一个 npm 命令把受控来源清单同步到仓库内专用工作目录，并获得结构清晰的 Markdown、逐页元数据、来源清单和同步报告。
- 每个页面必须同时校验允许域名、固定修订号和预期原始 Wikitext SHA-256；任一校验失败时该页不得进入成功清单，命令最终返回非零。
- 清洗结果保留标题、段落、强调、嵌套列表、定义列表、表格、图片说明和安全内部引用，清除脚本、样式、表单、目录、编辑入口、导航和 MediaWiki 缓存注释。
- 固定样本覆盖正常页面、危险节点、复杂链接、列表、表格、图片、重定向、重复内容和失败报告；自动测试不访问真实 Wiki。
- 真实站点单页烟雾验证通过，且最终 Git 差异不包含下载的 HTML、Wikitext、图片或生成的官方规则正文。

## 用户与使用场景

直接用户是维护官方知识包的开发者和评审者。开发者在官方来源清单确认或升级后执行同步命令，查看报告中的成功、失败、重定向、重复和待核对链接，再决定是否进入后续索引流程。M2-R3 的索引生成器消费本工具的规范 Markdown 与元数据；房主、说书人和玩家不直接触发在线抓取。

## 已确认需求

- 命令入口为 `npm run knowledge:sync`，默认读取仓库内版本化配置和 M1-R1 现有来源清单，默认输出到 `.work/m2-r2-wiki-sync/output/`。
- 当前 39 个固定修订用于实现和验证 M2-R2 输入契约，不因此把 M2-R1 的完整规则源核对标记为完成。后续 M2-R1 可扩充或替换来源清单，工具不得要求修改清洗代码。
- 同步器只抓取来源清单中显式选择的固定修订。正文内发现的其他 Wiki 页面仅规范化、去重并写入“待核对候选”报告，不自动抓取，也不自动成为规则事实。
- 每页同时抓取固定修订 HTML 与 MediaWiki API 返回的原始 Wikitext。HTML 用于 DOM 清洗；Wikitext 只用于修订元数据和 SHA-256 完整性校验，不写入最终产物。
- 网络请求串行执行并遵守配置的最小请求间隔，携带明确 User-Agent，具有超时、最大响应体、有限重试和 `Retry-After` 退避。只重试限流、服务端错误和短暂网络错误，不重试内容或完整性校验失败。
- 输出目录采用工具所有权标记和临时目录发布。已有非本工具目录不得被覆盖；失败运行仍生成完整报告，但只有校验成功的页面进入成功清单。
- 真实 Wiki 正文及现场下载只保存在被 Git 忽略的 `.work/` 中。本需求只提交工具、配置、Schema、虚构固定样本、测试和文档，避免在来源许可与发布策略尚未独立确认前把正文纳入仓库。

## 范围

- 定义 Wiki 同步配置、逐页元数据、成功清单和报告的版本化格式。
- 从已有规则范围清单读取固定来源，校验配置、来源字段、允许域名、修订号和哈希格式。
- 实现受限 HTTP 客户端、MediaWiki 固定修订 HTML/API 获取、取消、超时、限流退避和响应体上限。
- 使用 HTML 解析器定位 `.mw-parser-output`，清除危险及站点展示节点并提取页面标题、修订和内部链接。
- 规范化 MediaWiki `/index.php?title=`、`/wiki/`、相对链接、锚点和图片 URL；拒绝跨域图片、危险协议、特殊命名空间、编辑/历史/登录等非正文动作。
- 转换并规范化 Markdown，使用稳定来源 ID 作为文件名，避免中文标题、重定向或同名页面造成路径冲突。
- 输出 `official/<language>/` Markdown、`sources/` 逐页元数据与清单，以及 JSON/Markdown 同步报告。
- 报告失败、重定向、内容重复、待核对链接、被拒绝链接和清洗统计。
- 提供纯函数单元测试、带假 HTTP 的同步集成测试和显式启用的单页在线烟雾命令。

## 非范围

- 不在本需求内补齐 M2-R1 的角色资料、规则说明、相克、勘误和英文缺失补充清单，也不判断新发现页面是否权威或应被收录。
- 不自动翻译英文内容，不调用 LLM，不建立英文产品环境。
- 不生成浏览器搜索索引、切分向量、召回排序或 Agent `rules-search` Skill；这些属于 M2-R3 及后续需求。
- 不下载或重新托管 Wiki 图片；Markdown 只保存经过允许域名校验的原始绝对图片引用与替代文本。
- 不修改规则内核、对局状态、Vuex、WebSocket、浏览器存储或现有 UI。
- 不默认连接真实站点运行测试，不把完整 Wiki 快照提交到 Git，也不自动部署任何产物。

## 规则与裁量边界

同步器不解释或执行桌游规则。来源优先级、中文优先和英文缺失补充策略沿用 M1-R1；工具只验证来源身份并忠实清洗结构，不在中英文冲突时自动合并、覆盖或裁决内容。

当前来源记录的 `revision`、`revisedAt` 和 `contentHash` 是固定事实。HTML 中的实际修订、API 返回修订和计算得到的 Wikitext SHA-256 必须全部一致。页面当前最新版本、导航推荐、分类页和正文新链接不是规范来源；只作为报告候选交给后续来源核对。

## 交互与失败恢复

- 正常流程：读取配置与来源清单，逐页请求并校验，清洗成功页，汇总报告，最后以临时目录原子发布到目标目录。
- 进度输出只包含来源 ID、阶段和可操作错误，不输出完整正文、Cookie、请求头或其他敏感内容。
- 用户按 Ctrl-C 时停止新请求并取消当前请求，清理未发布临时目录，以非零退出；已存在的上一版成功输出保持不变。
- 请求超时、429 和 5xx 按配置退避重试；404、跨域重定向、响应过大、解析失败、修订不符和哈希不符直接记录失败。
- 单页失败不阻断其他已选择页面的诊断收集；全部页面结束后生成失败报告并返回非零。再次执行会从来源清单重新校验，不使用未验证缓存。
- 输出目标已存在但没有工具所有权标记时拒绝覆盖，并提示改用空目录或专用工作目录。

## 状态、事件与权限

本需求不新增对局状态、命令或领域事件。同步产物是构建期文件：

- 逐页元数据记录格式版本、来源 ID、标题、语言、权威级别、请求 URL、最终 URL、修订、页面更新时间、抓取时间、Wikitext/HTML/Markdown 哈希、可信边界和链接统计。
- 成功清单只引用校验成功且已落盘的页面，不包含正文；同步报告另行记录失败和候选。
- Markdown 与 Wiki 文本统一标记为 `untrusted-external-content`。该标记不授予任何 Agent 工具或规则写入权限，M2-R3 及 Agent Runtime 必须继续在检索结果外层声明不可信数据边界。
- 输出不包含 API Key、Cookie、授权头、真实玩家信息、对局隐藏身份或私聊。

## Agent、Skill 与 LLM 约束

本需求不运行 Agent、不新增 Skill、不调用 LLM，也不处理供应商差异、Token、费用或模型降级。网页中出现的命令式文本只能作为普通规则正文保存，不能改变同步器配置、网络白名单、输出路径或进程权限。后续规则检索必须返回来源、修订和匹配片段，并继续把正文作为不可信数据传给 Agent。

## 兼容、迁移与回滚

- 工具使用独立 Node.js 构建脚本和开发依赖，不进入浏览器生产包，不改变 Vue 2、现有页面或在线协议。
- 配置、元数据和报告均含格式版本。后续不兼容变更必须升级格式版本；M2-R3 只消费明确支持的版本。
- 当前 M1-R1 来源清单保持不变；M2-R1 后续扩充来源时通过新清单版本接入。
- 回滚可删除本需求新增脚本、配置、测试、依赖和文档，并清理被忽略的 `.work/m2-r2-wiki-sync/`，不需要迁移对局或浏览器数据。

## 实现计划

2. 实现配置读取、MediaWiki 解析与清洗纯函数，使单元测试通过。
3. 增加假 HTTP 同步集成测试，实现请求策略、逐页元数据、报告和安全发布。
4. 增加 npm 命令与文档，执行显式单页在线烟雾验证，但不提交现场内容。

## 当前实现基线

- 新增 `scripts/wiki-sync/` 构建工具，按配置读取 M1-R1 现有来源清单，提供配置/来源校验、MediaWiki URL 规范化、固定修订 API 解析、DOM 清洗、GFM Markdown、受限 HTTP、同步编排、双格式报告和受保护原子发布。命令入口为 `npm run knowledge:sync`，支持重复 `--only`、自定义仓库内输出目录、帮助和信号取消。
- 新增同步配置以及配置、逐页元数据、成功清单、同步报告四份 Draft-07 Schema。逐页元数据记录不可信边界、请求/最终 URL、修订、页面时间、抓取时间、Wikitext/HTML/Markdown 哈希、链接统计和清洗统计；集成测试会实际校验生成 JSON。
- 清洗器使用 Cheerio DOM 和 Turndown GFM 插件，清除脚本、样式、表单、嵌入内容、目录、编辑入口、缓存注释、事件属性和非必要属性；保留标题、段落、强调、引用、嵌套列表、定义列表、表格、代码和同源 HTTPS 图片。危险协议、不安全 HTTP、特殊命名空间、编辑/红链和跨域图片均被拒绝或降为普通文本。
- 已选择且实际生成的页面改写为稳定本地链接；清单内但 `--only` 未生成的页面保留固定在线修订；清单外正文页只进入规范化候选报告。重复候选按标题合并，重复正文按 Wikitext SHA-256 分组。
- 请求使用 `ClocktowerKnowledgeSync/0.1` 显式 User-Agent、串行一秒最小间隔、15 秒超时、4 MiB 上限和最多两次有限退避重试。该名称用于避开站点 WAF 对 User-Agent 中 `BotC` 字样的误拦截，仍保留维护者联系地址且不伪装浏览器。
- 输出使用 `.botc-wiki-sync-output` 所有权标记和同目录临时目录原子发布。非工具目录会被拒绝；取消时不发布；已有成功输出后的失败重跑只写入同名 `.failed` 旁路目录，不覆盖上一版成功结果。
- 虚构固定样本包含危险节点、复杂链接、嵌套列表、定义列表、GFM 表格、同源/跨域图片、引用和代码。新增 26 个 Wiki 单元测试及 4 个集成测试，连同既有用例共 62 个 Jest 测试；Wiki 模块设置语句 75%、分支 60%、函数 70%、行 75% 的独立覆盖率下限。
- 显式单页现场烟雾和全部 39 个固定中文修订巡检均通过。完整巡检结果为成功 39、失败 0、候选页 237、拒绝链接 0、重复内容组 0；结构审计确认 39 份 Markdown 均有标题，0 个断裂本地链接、0 个危险协议/事件属性、0 个跨域图片，并保留 249 个同源图片引用。现场产物仅位于 `.work/m2-r2-wiki-sync/`，没有进入 Git。
- Node.js 22.17.1 与 npm 11.13.0 下 `npm ci`、`npm run test:coverage` 和 `npm run test:ci` 通过。完整门禁包含 52 个单元测试、3 个组件测试、1 个场景测试、6 个集成测试、415 条遗留 Lint 警告预算、生产构建和 3 个 Chromium 端到端场景；新增文件的独立 ESLint 检查为 0 错误、0 警告。

## 验收标准

- 需求文档不存在影响实现的待确认项，当前清单与未来 M2-R1 清单的边界明确。
- `npm run knowledge:sync -- --only <source-id>` 能同步一个固定修订；无 `--only` 时处理清单中全部来源。
- 来源 URL 不在允许域名、缺少固定修订、HTML/API 修订不一致或 Wikitext 哈希不符时，对应页失败且命令返回非零。
- 固定样本的脚本、样式、表单、目录、编辑入口、事件属性、危险协议和跨域图片不进入 Markdown。
- 标题、段落、强调、嵌套列表、定义列表、表格、图片替代文本、安全链接和中文标点保持可读，连续空白稳定规范化。
- 内部页面链接按标题规范化并去重；已选择来源指向稳定本地文件，未选择正文页进入候选报告；特殊命名空间和非查看动作被拒绝。
- 重定向、重复内容、被拒绝链接、清洗计数和每类失败均可在机器可读 JSON 及中文 Markdown 报告中定位到来源 ID。
- 输出目录发布不会覆盖非本工具文件；取消或失败不会破坏上一版成功输出。
- 自动测试不访问外网；显式在线烟雾验证只处理一个固定页面，遵守请求间隔并把产物留在 `.work/`。
- 产品、架构、知识目录、文档索引和路线图与最终实现一致；Git 差异不含现场页面、官方正文、图片、密钥或 Cookie。
- 针对性测试、覆盖率、Lint、生产构建和 Chromium 端到端测试全部通过，然后仅创建本地提交，不 Push。

- 覆盖率：新增同步与清洗模块纳入 Jest 覆盖率收集，关键分支必须由有效断言触发；不以遗留 UI 的低覆盖率替代新模块测试。
- 回归：运行 `npm run test:coverage` 和 `npm run test:ci`；本需求无 UI 行为变化，不新增专用 Playwright 场景，但保留既有 Chromium 回归。
- 安全检查：搜索 Git 差异与测试快照，确认没有下载正文、Cookie、密钥、真实会话数据、危险 URL 或工作目录产物。
- 人工检查：对固定样本和单页现场输出抽查标题层级、列表缩进、表格、图片说明、内部链接与报告可读性。

## 风险与待确认项

当前没有影响实现的待确认项。

中文官方 Wiki 的 `/robots.txt` 当前由站点重写为普通 Wiki 页面，未返回独立 robots 规则；本工具因此采用显式 User-Agent、串行请求、默认一秒最小间隔和有限重试的保守策略。站点 WAF 会误拦截 User-Agent 中的 `BotC` 字样，因此同步器使用不含该字样的 `ClocktowerKnowledgeSync` 工具名并保留维护者联系地址，不伪装成浏览器。来源许可与完整正文提交策略尚未在独立需求中确认，因此本需求不提交真实正文或图片。站点模板和 MediaWiki 版本未来可能变化；固定样本、正文选择器失败报告和格式版本用于阻止静默生成残缺内容。
