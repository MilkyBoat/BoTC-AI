## 背景与问题

项目需要从成熟的在线魔典出发，重新设计支持 AI 说书人和 AI 玩家的浏览器端架构。此前相邻目录中的实验项目以命令行说书人为中心，其业务模块、状态模型和 Agent 组织方式不符合本项目方向，不能复制；其中对规则 Wiki 的页面发现、正文抽取、链接规范化和 Markdown 知识库生成思路可以作为后续重新实现的参考。

仓库初始化还需要建立不依赖第三方 Spec 套件的文档驱动开发流程，使长期迭代中的每项需求在实现前消除歧义，并持续维护连贯的全量产品文档。

## 已确认需求

BotC-AI 基于 `bra1n/townsquare` 二次开发，继承魔典、在线房间、角色分发和投票等能力。对局中的说书人由 AI 承担，玩家席位允许在规则支持的总席位范围内配置任意数量的 AI，因而支持全人类、混合和全 AI 对局。

Agent 编排、Skills、私密上下文和对局决策均运行在房主浏览器。LLM 推理可以调用 OpenAI、Claude、DeepSeek、火山方舟或本地部署模型，但供应商差异必须由统一适配层隔离。在线会话服务不得获得完整魔典、模型凭据或 Agent 私密记忆。

AI 说书人由通用 Agent 框架、说书人系统提示词和说书人 Skills 组合而成，Skills 至少覆盖公开/私密交流、魔典状态读写、流程推进和官方规则检索。AI 玩家由同一 Agent 框架、玩家系统提示词和玩家 Skills 组合而成，Skills 至少覆盖与玩家/说书人交流、合法游戏动作、私有笔记和官方规则检索。

第一阶段交付完整可玩的 AI 在线对局。第二阶段在稳定规则内核、回放和评测体系上探索开源 LLM 的自博弈、数据生成和强化学习微调。

## 架构决策

- 采用“确定性规则内核 + 事件日志 + 权限视图 + 浏览器内 Agent Runtime”的分层方案。
- Agent 通过有类型、可审计的工具提交意图，不直接修改 Vuex 或序列化魔典。
- 说书人和玩家共享 Agent Runtime，但使用不同系统提示词、Skills、工具权限和观察视图。
- 人类玩家与 AI 玩家使用同一动作协议，AI 席位通过房主浏览器内的本地传输接入。
- 规则知识采用离线同步、版本化索引和带来源检索，不在对局关键路径实时抓网页。
- 官方英文 Wiki 作为主要在线规则来源；中文社区资料可以作为本地化辅助，但不能覆盖官方规则结论。

## 风险与处理

- 上游已停止主动维护：通过固定基线、独立同步需求和回归测试控制长期分叉风险。
- Vue 2 与旧版 WebSocket 依赖存在升级压力：先建立行为基线，再按需求渐进迁移，避免初始化时重写。
- 上游代码默认连接公共会话地址：在会话传输重构完成前，只允许本地构建，不启动真实在线房间测试。
- 官方规则持续更新：知识快照必须记录来源 URL、抓取时间和内容版本，并支持重新索引。
- 浏览器直连不同 LLM 可能受 CORS、Key 暴露和供应商协议约束：Provider 需求需分别确认直连、用户自托管网关和本地模型模式。
