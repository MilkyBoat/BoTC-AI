# 安全开发会话环境

## 元信息

- 状态：本地完成
- 创建日期：2026-07-16
- 关联里程碑：[M0-R4 安全开发会话环境](../milestone/roadmap.md#m0固定源码基线与开发治理)
- 负责人：Codex

## 背景与问题

当前前端把 `wss://live.clocktower.online:8080/` 直接写在会话客户端中。首次打开且没有房间 Hash、没有旧本地会话的页面不会立即建立连接，但开发者只要建房、加入房间、打开带房间 Hash 的链接，或浏览器恢复了 `localStorage` 中的旧会话，就会连接该公共外部服务。

仓库已经包含可在本地运行的 WebSocket 中继，但现有说明要求开发者手工修改 `src/store/socket.js`，没有稳定的 npm 启动入口，也没有把开发中继明确限制在本机。M0-R3 的端到端用例只验证空状态首页没有外部请求，尚未覆盖建房、Hash 入会、旧会话恢复和本地中继转发。因此当前状态不满足“开发和测试不得连接外部生产服务”以及 M0 的本地房间验收要求。

本需求只建立安全、可复现的开发会话闭环。后续领域事件、权限视图和在线协议重构仍由 M1 及后续独立需求承担。

## 目标与成功标准

- 源码和默认生产构建不再内置公共会话服务地址。
- 本地开发页面默认只连接运行在 `127.0.0.1:8081` 的仓库内中继，开发者无需修改源码。
- 生产构建只有在显式提供合法 WebSocket 中继地址时才启用在线会话；未配置或配置非法时保持离线可用并向用户说明原因。
- 开发者按 README 使用两个终端即可启动前端与本地中继，并能在两个浏览器页面中建立同一房间。
- 自动测试覆盖配置解析、本地中继转发、建房/Hash 入会及外部 WebSocket 阻断。
- `npm run test:ci` 全量通过，且不访问公共会话服务、真实玩家数据或其他线上依赖。

## 用户与使用场景

主要用户是本项目开发者和代码评审者：

- 开发者在本机启动前端和中继，通过房主页面建房，并用另一个浏览器页面或上下文作为玩家加入。
- 开发者从带房间 Hash 的本地链接加入，或浏览器恢复上次本地房间。
- 评审者运行单元、集成和端到端测试，确认所有会话连接均留在本机。
- 未来部署者在构建时显式配置受控的 `wss:` 中继；M0-R4 不提供该中继的部署服务。

本需求不改变正式对局中的房主、玩家、说书人或旁观者规则行为。

## 已确认需求

- 使用 `VUE_APP_SESSION_RELAY_URL` 作为前端构建期会话中继配置。
- 开发模式未提供配置时，使用 `ws://127.0.0.1:8081/`；测试和生产模式不使用隐式远端地址。
- 生产模式未配置中继时不阻断离线生产构建，而是禁用在线会话入口并显示“未配置会话中继”提示。
- 显式配置只接受 `ws:` 或 `wss:` URL；拒绝用户名、密码、查询参数和 Hash，并统一补齐末尾斜杠。非法配置与未配置一样禁止连接，但提示应区分原因。
- 本地中继通过独立的 `npm run relay:dev` 启动，默认绑定 `127.0.0.1:8081`，只接受明确允许的本地前端 Origin。
- 本地开发使用两个终端分别运行前端和中继；不为一个组合命令新增仅用于进程并发的依赖。
- 本阶段不部署公共测试环境；README 明确测试只使用本地中继。
- 保留现有 townsquare 会话消息语义，不在本需求中修改消息格式或业务同步逻辑。

## 范围

- 新增独立、可单元测试的会话中继配置解析模块。
- 会话客户端使用解析后的配置，不再包含或回退到 `clocktower.online` 地址。
- 会话状态记录中继是否可用及不可用原因；无可用中继时拒绝建房、加入、Hash 自动入会和旧会话自动恢复。
- 在线会话不可用时，在会话菜单显示状态；键盘快捷键或方法直接触发建房/加入时也不得建立连接。
- 为本地中继增加 npm 启动入口、可配置端口/地址/Origin，并使开发默认值仅监听本机。
- 增加配置单元测试和真实本地中继转发集成测试。
- 扩展 Playwright，使测试期间同时启动本地前端和本地中继，并覆盖房主建房与玩家通过 Hash 加入。
- 重写本地开发、会话中继和测试说明；同步需求索引、产品当前状态和里程碑状态。

## 非范围

- 不重写 WebSocket 消息协议，不增加领域事件、幂等键、版本协商或权限过滤。
- 不实现端到端加密、私聊安全协议、会话持久化迁移或断线检查点。
- 不部署测试、预发或生产中继，不连接或修改 `clocktower.online`。
- 不实现 Agent、Skill、LLM Provider、规则内核或 AI 席位本地传输。
- 不升级 Vue、Vuex、`ws` 或现有生产依赖。
- 不修复与本需求无关的遗留 Lint 警告和上游界面问题。

## 规则与裁量边界

本需求不新增或修改血染钟楼规则，官方规则版本和说书人裁量均不适用。中继只转发现有消息，不解释、验证或更改游戏行为。后续规则内核不能把本需求保留的旧会话协议视为规则事实。

## 交互与失败恢复

- 本地开发者先运行 `npm run relay:dev`，再运行 `npm run serve`；顺序相反也允许，但在中继未启动时连接失败应沿用现有重连状态，不回退其他地址。
- 会话中继可用时，房主和玩家入口维持现有提示框和房间 ID 流程。
- 中继未配置或配置非法时，会话菜单显示不可用原因，房主/加入入口不再弹出房间输入框，也不写入会话持久化。
- 页面从旧 `localStorage` 恢复会话但当前中继不可用时，清除活动会话 ID，保留其他魔典数据，避免页面显示为已联网。
- 带房间 Hash 的页面在中继不可用时不加入房间，并移除活动会话 Hash；不自动跳转或尝试公共服务。
- 本地中继启动端口被占用、Origin 不被允许或连接失败时明确返回非零退出或连接错误；不得选择随机远端服务作为降级。
- 取消开发进程后不保留额外临时文件；测试负责终止其启动的中继和浏览器。

## 状态、事件与权限

会话 Vuex 状态新增只读展示用途的中继状态：是否可用、规范化 URL 和用户可读原因。该状态由会话插件初始化，不写入 `localStorage`，也不通过 WebSocket 同步。

现有 `sessionId`、`isSpectator` 和玩家会话状态的持久化格式保持不变。无可用中继时可以通过既有 `setSessionId("")` 清理旧活动会话，不迁移或重写其他本地数据。

本需求不新增领域命令或领域事件。中继仍无法区分 StorytellerView、SeatView 和 PublicView；这一权限缺口必须在 M1 的协议与权限视图需求中解决，M0-R4 不扩大中继可见数据。

## Agent、Skill 与 LLM 约束

本需求不运行 Agent、不新增或修改 Skill、不调用 LLM，也不引入 Provider 配置。会话中继配置不得与未来模型 Key 共用变量、状态或持久化路径。测试使用虚构房间和消息，不包含真实提示词、玩家私聊或隐藏身份。

## 兼容、迁移与回滚

- 原公共中继不再是隐式默认值；确需连接任何受控远端中继时，部署者必须显式设置 `VUE_APP_SESSION_RELAY_URL`。
- 现有会话路径 `/<channel>/<playerId|host>` 和消息内容保持兼容。
- 开发默认从手改源码切换为本地安全默认值；`.env.example` 说明如何显式覆盖。
- 旧浏览器中的活动会话在无中继配置时会被退出，其他魔典和角色数据不受影响。
- 回滚可撤销本需求提交恢复固定源码行为；回滚后会重新出现隐式公共服务风险，因此只能用于本地诊断，不能作为正式发布方案。

## 验收标准与结果

本地验收使用 Node.js 22 完成。`npm run test:ci` 依次通过 12 条单元测试、3 条组件测试、1 条场景测试、2 条真实本地中继集成测试、415 条遗留 Lint 警告预算、生产构建和 3 条 Chromium 端到端测试。端到端覆盖空状态、本地房主与 Hash 玩家联机、玩家状态同步以及旧本地会话恢复，所有业务 WebSocket 均指向 `127.0.0.1:8081`。

`npm run test:coverage` 通过 7 个测试套件、18 条非端到端用例，当前全仓覆盖率为语句 9.53%、分支 7.29%、函数 9.14%、行 9.67%，不作为全仓门禁阈值。真实中继测试同时验证允许 Origin 的房主/玩家消息转发以及非法 Origin 拒绝。GitHub Actions 因本需求不 Push 而未触发远端运行。

- 全仓搜索确认生产源码中不存在 `live.clocktower.online` 或其他默认公共会话 URL。
- `resolveSessionRelayConfig` 对开发默认值、显式本地/远端值、生产缺省值和非法值给出确定结果。
- 生产缺少配置时页面可正常构建和加载，会话菜单显示不可用，建房和加入不会创建 WebSocket。
- `npm run relay:dev` 在 `127.0.0.1:8081` 启动，不需要证书或源码修改。
- 两个本地 WebSocket 客户端能够经中继完成一条虚构消息转发；不允许的 Origin 被拒绝。
- Playwright 中房主建房与玩家通过 Hash 加入产生的业务 WebSocket URL 均为本地地址；测试观察不到公共会话服务的 HTTP 或 WebSocket 请求。
- README 的命令在干净安装后可执行，M0 路线图和产品当前状态与实现一致。
- 完整测试、Lint、生产构建和 Chromium 端到端测试通过，遗留警告不增加。

## 测试方案

- 单元测试：配置缺省、覆盖、规范化和非法 URL；会话状态更新及无中继时的拒绝行为。
- 组件测试：会话菜单在中继不可用时显示原因且不触发建房输入。
- 集成测试：启动真实本地中继，使用房主和玩家两个 `ws` 客户端验证转发及 Origin 拒绝。
- 端到端测试：空状态首页不访问外部服务；本地房主建房、Hash 玩家加入与持久会话恢复只连接本地中继。
- 回归测试：既有 session Vuex 场景测试、全部分层测试、Lint 和生产构建继续通过。
- 人工检查：按 README 在两个终端启动服务，并在两个本地浏览器页面确认同一房间；不使用线上房间或真实数据。

## 风险与待确认项

无影响本次实现的待确认项。正式远端中继的域名、部署、证书、监控、隐私和审批属于 M5-R8；会话协议权限与信息最小化属于 M1，均不得在本需求中预先假定。
