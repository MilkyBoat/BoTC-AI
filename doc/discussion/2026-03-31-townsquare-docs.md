# 沟通记录（2026-03-31）

## 主题

TownSquare 合并与智能主持人阶段性需求文档拆分（含阶段一聊天模块细化）

## 用户原始想法

- 将 townsquare 代码合并入当前项目，全部改造完成后删除 townsquare 目录
- 主持人 web 端新增配置表单，允许输入 API_KEY 等原本从 .env 读取的配置，保存到 localStorage 并可修改
- 现阶段支持 server 侧 .env 注入默认配置用于调试
- AI 运行在主持人 web 端内置模块，不走任何网络桥接
- AI 在 web 端运行时可直接修改主持人端游戏状态，并同步给玩家
- 本期先实现全自动模式，未来再实现半自动模式
- 架构上需要预留人类介入入口，允许人类手动调整状态或私聊玩家，并以“特殊工具调用”的方式把修改写入 AI 上下文
- 需求拆分为四阶段文档，每阶段一个需求文档和一个技术方案，方案要细化到代码模块
- 额外新增整体架构设计文档，明确模块关系、职责与交互方式
- 细化阶段一聊天需求：
  - 页面左侧常驻可收起模块
  - 聊天记录格式为 `【X】message content`，X 优先显示名称
  - Host 输入框左侧下拉选择对象，或使用 `@all` / `@3` 指定
  - Player 仅允许与主持人私聊，不支持选择
  - 预留公开函数供 AI 发送与接收消息
- 开始阶段一需求开发，按上述细化要求落地到代码
- 新增布局调整要求：
  - 将中央的剧本名称、总人数、阵营人数移动到左上角
  - 聊天框与 bluffs 使用统一风格、统一按钮位置与相同动画
  - bluffs 展开时，聊天框底边自动上缩避让
- 布局进一步修正：
  - bluffs 收起时，聊天框也不能遮挡其标题栏
  - 剧本图片回到画面中心，左上角仅保留名称与人数信息
  - 每类人数信息保持单行展示，并兼容未来更多阵营类型
- 进一步微调：
  - 左上角信息区不需要背景和边框
  - 聊天框收起时，宽度也应缩到只保留最小可读标题栏
- 修正实现细节：
  - 左上角信息区当前位置异常，需要重新固定到页面左上角
- 聊天显示细节调整：
  - 主持人消息标题需要使用强调色
  - 主持人私聊消息标题改成 `【主持人对xxx私聊】`
- 可见性补充：
  - 聊天模块仅在进入对局后展示，未进入房间时隐藏

## 我的思路与判断

- 将文档从“单一总体方案”拆分为“阶段一至阶段四”需求与技术方案，确保每期目标与交付可清晰验收
- 统一约束：AI 全部运行在主持人浏览器端，状态修改通过 Vuex mutation 触发，同步机制仍复用原 WebSocket socket layer
- 配置策略设计为：localStorage > .env 注入默认值 > 空值，满足调试与可修改需求
- 半自动模式与监督者介入设计为未来入口，通过“监督者操作日志 + 上下文附加机制”在架构上预留
- 每阶段技术方案细化到模块与路径层级，确保后续实施时可直接对照落地
- 阶段一聊天模块补充到具体 UI 与输入规则，并明确 AI 预留接口位置
- 在 townsquare 代码中实现聊天模块的 UI、Vuex、socket 与 AI 公开接口
- 将 TownInfo 改为左上角紧凑信息面板，并用共享面板状态协调聊天框与 bluffs 的避让
- 继续微调为“信息面板与中心 logo 分离”，并让聊天框在 bluffs 展开/收起两种状态下都留出安全边距
- 把左上角信息面板改成纯文字叠加层，并让聊天收起态宽度同步收缩
- 识别到全局 `* { position: relative; }` 会影响信息区定位，因此需要显式把信息区改为固定定位
- 在聊天展示层做轻量格式增强，不改动现有消息协议主结构
- 聊天面板显隐以 session 状态作为准入条件，避免在大厅态提前暴露空面板
