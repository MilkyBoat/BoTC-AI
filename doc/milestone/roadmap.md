# BotC-AI 长期里程碑规划

## 总体路线

第一阶段交付严格遵循规则、支持在线人机混合对局的浏览器产品；第二阶段在同一规则内核上建设自博弈、评测和强化学习闭环。每个表格条目都必须在实施前创建独立的 `doc/modify/` 需求文档并完成反问澄清。townsquare 仅作为固定初始源码快照保留，未来不主动跟踪或同步其仓库。

## M0：固定源码基线与开发治理

结果：仓库拥有可构建的 townsquare 固定基线、明确的长期产品/架构规划、Spec 文档流程与可持续的本项目测试门禁。

| 编号 | 需求 | 交付结果 | 依赖 | 状态 |
| --- | --- | --- | --- | --- |
| M0-R1 | 项目基线与规划初始化 | 导入固定上游快照，建立文档、模板、AGENTS、验证与本地提交 | 无 | 本地完成，关联发布受阻 |
| M0-R2 | 上游行为基线 | 原计划为魔典、角色分发、在线同步和投票建立全量行为清单；因初始源码已固定且不再跟踪上游，本阶段不实施 | M0-R1 | 已跳过 |
| M0-R3 | 本项目测试基础设施 | 建立单元、组件、场景和端到端测试入口，接入本地与 CI 门禁 | M0-R1 | 本地完成 |
| M0-R4 | 安全开发会话环境 | 移除隐式公共中继，提供安全配置、本地中继、集成测试和开发说明 | M0-R3 | 本地完成 |

里程碑验收：新开发者按 README 能在不连接外部生产服务的情况下安装、测试、构建和启动本地房间；本项目新增和后续修改的行为具有分层回归保护。

M0 已在本地完成。关联提交默认不 Push；远端门禁状态不作为开始 M1 需求澄清的前置条件，但后续发布仍需独立审批。

## 全局决策门

以下问题会显著改变实现，每个相关里程碑启动时必须通过需求反问确认，而不是沿用默认猜测：

- 首发严格支持的中文剧本、角色、玩家数以及旅行者、传奇角色、奇遇角色和实验性角色范围。
- 房主对 AI 说书人的审批粒度，是逐动作确认、关键动作确认还是默认自治。
- 浏览器直连 API Key、用户自托管网关和本地模型三种模式的首发优先级。
- 私聊是否需要端到端加密，以及在线中继的部署与信任边界。
- 对局保存、玩家同意、训练数据授权和模型训练许可证范围。
- 目标浏览器、移动端、无障碍、国际化和性能基线。
